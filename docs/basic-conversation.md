# 기본 대화 및 무러바라 페르소나

## 지원 범위

- 이름은 무러바라이며 LG U+ 통신 고객센터 AI 상담사로 소개한다. 친근한 존댓말을 사용한다.
- 순수 인사·감사·작별·호출·자기소개·도움말·안부는 규칙으로 처리하며 분류/답변 모델 호출을 하지 않는다.
- 이름/호칭과 표현 목록은 `BasicConversationClassifier`, 고정 응답은 `ChatPersona`에서 관리한다.
- 무러바라, 무러봐라, 물어바라, 물어봐라, 무러바, 바라, mureobara 및 야/님/씨 호칭을 지원한다.
- 공백, 일부 문장부호, 대소문자·전각 문자 차이를 판별용 복사본에서 정리한다. 원문은 변경하지 않는다.
- `ConversationInput`은 장식 이모지를 분석 입력에서 제외하며 숫자 키캡은 숫자로 보존한다. 통화·수학 기호를 일괄 삭제하지 않는다.
- 앞 표시 `[문의]`, `[질문]`만 호칭보다 먼저 정리한다. 상품명 등 다른 대괄호 내용은 보존한다.
- 이모지·기호만 보낸 경우 글로 질문하도록 안내하며 기존 상담 상태·재질문 횟수를 유지한다.
- 문장 전체가 등록된 기본 표현과 호칭으로 구성되어야 고정 응답으로 끝낸다. 모든 오타·자유 잡담을 지원하지 않는다.
- 기본 응답에 이모지를 하나 사용한다. FAQ와 혼합 인사에는 이모지를 추가하지 않는다.
- 작별은 세션 종료나 상담 취소 요청이 아니다.

| 입력 | 처리 |

| 바라야 / 무러바라야 | 호출 응답 |

| 안녕 바라야, 유심 비용 알려줘 | 기존 상담 분석 및 FAQ 처리 후 인사 1회 |
| 강남역이요, 고마워요 / 네, 고마워요 | 기존 조건 후속 처리 |
| 이름이 포함된 상품·정책 질문 | 기존 상담 분석 |

## 판단 순서

1. `ConsultTurnAnalysisAdapter`가 검증된 문맥의 실행·메시지·세션 관계를 확인한다.
2. 좌표 입력이 없는 순수 기본 대화는 질문 문맥 복원 및 후속 조건 분석 전에 처리한다.
3. 원문은 저장·안전 검사·이력에 보존하고, 나머지 상담에는 `ConsultationQuestion`이 추출한 본문을 공통으로 전달한다.
4. FAQ 생성에 짧은 페르소나 시스템 지침을 포함하되 기존 근거·비교·출력 규칙을 유지한다.
5. 최종 저장 직전에 명확한 혼합 인사에만 짧은 인사를 한 번 붙이고 전체 출력 검사를 수행한다.
6. 최종 전송에도 동일한 조합 함수를 적용한다. 모델 중간 출력은 직접 전송하지 않는다.

## 대기 중 기본 대화

- 기존 대기 상담이 있어도 순수 기본 대화는 고정 응답과 대기 질문을 함께 안내한다.
- 여러 질문이 대기 중이면 임의 조건을 선택하지 않고 일반적인 후속 안내를 한다.
- 기본 응답은 `ANSWER`, 실행/메시지는 `COMPLETED`, `answerBasis`는 null로 저장한다.
- `persistBasicConversation` / `completeBasicConversation`은 세션 대기 상태를 유지한다.
- 상담 요청·조건·대기 질문 ID·재질문 횟수·상담 버전을 변경하지 않는다.
- 다음 실제 조건 답변은 기존 상담에 연결한다. 이미 재질문 상한에 도달해도 기본 대화로 조건을 거절하지 않는다.
- 좌표가 함께 들어온 메시지는 상담 분석에 남겨 실제 위치 조건이 사라지지 않게 한다.

## 프로필과 근거 부족 안내

- `ChatPersona.ANSWER_INSTRUCTIONS`를 필요한 FAQ 생성 요청마다 기존 시스템 프롬프트에 포함한다.
- `rag-answer-v4.6-persona`와 `persona-v2`로 프롬프트/정체성 버전을 구분한다.
- 프로필은 정책 근거가 아니다. 사용자 요청으로 역할·정체성·FAQ 제한을 변경하지 않는다.
- 새 근거 부족 문구는 `AnswerPromptTemplates.NO_EVIDENCE_ANSWER`에서 관리한다.
- 마침표 없는 근거 부족 출력도 Guard가 정규 문구로 정리한다. 답변 근거는 인사를 붙이기 전에 판정한다.
- 과거 저장 메시지를 새 문구로 일괄 변경하지 않는다.
- 규칙 기본 대화의 분류/답변 호출과 별개로 기존 제목·요약 후처리는 유지한다.

## 저장·조회·안전 계약

- 기본 대화는 상담 요청이나 FAQ 출처를 새로 만들지 않는다.
- 기존 입력/출력 안전 검사와 실행·세션 잠금을 재사용한다. 검사 차단·오류는 기존 안전 실패 경로를 따른다.
- 직접 답변은 저장 후 기존 `complete` 이벤트로 출력 메시지 ID를 반환한다. 내용은 이력 조회로 확인한다.
- 상담 답변의 token/complete와 저장된 최종 응답은 같은 인사 조합을 사용한다.
- 기본 대화와 고정 응답은 공통 규칙으로 문맥/요약 후보에서 제외한다. 혼합 상담 질문은 제외하지 않는다.

## 검증과 수동 확인

- 규칙 단위 테스트: 이름·호칭·7종 표현·혼합 질문·조건 답변·부분 문자열 오탐.
- 문맥 복원 모드가 LLM_ALL이어도 순수 기본 대화는 모델을 호출하지 않는지 검증한다.
- DB 통합 테스트: 저장/이력/완료 ID 일치, 대기 상태와 재질문 횟수 보존, 이후 지역 답변 연결.
- Guard 회귀 테스트: 새 근거 부족 문구 및 마침표 변형, 기존 사실·수치 제한 유지.
- 외부 AI/검색 서비스는 mock으로 대체한다. 실제 API 키 호출 테스트는 실행하지 않는다.
- 수동 확인 필요: 프론트 이모지·인사·매장 결과·되묻기 표시, 실제 모델 말투/정확성, 프로필 추가 전후 지연.
- 실제 모델과 화면을 확인하지 않았으므로 테스트 통과를 그 품질의 보장으로 해석하지 않는다.

## 혼합 상담 질문

- 분명한 앞·뒤 인사와 호칭·감사, 문장부호로 구분된 중간 기본 표현만 상담 본문에서 제외한다.
- 순수 기본 대화는 기존 고정 응답을 유지하며, 빈 상담 문장으로 바꾸지 않는다.
- 인용문·일반 단어·도메인명·금액·부정 표현을 보존하고, 애매한 중간 표현은 그대로 둔다.
- `보낼 내용: 안녕`처럼 본문을 명시한 표현은 보존한다. `.5GB`의 점은 제거하지 않는다.
- 뒤쪽 감사를 제거할 때 연결 쉼표만 함께 정리하고 본문의 마침표·물음표·느낌표는 보존한다.
- 문맥 복원 여부는 실제 출처 ID 유무로 전달한다. 인사 제거만으로 단일 질문의 원문 검색·검색어 의미 검증을 건너뛰지 않는다.
- 문맥 후보 판정·라우팅·검색·FAQ 프롬프트는 공통 추출을 사용한다. 원문과 분석 본문은 trace에서 구분한다.
- 검색은 같은 본문이면 한 번만 실행한다. develop의 단일 FAQ 재검색 의미 검증과 FAQ·매장 복합 상담은 유지한다.
- 기존 대기 질문은 인사를 제외한 질문 본문만 재안내한다. 상담 상태와 조건 ID는 바꾸지 않는다.
