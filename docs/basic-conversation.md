# 기본 대화 응답

## 지원 범위

- 대기 중인 상담 질문이 없을 때 인사·감사·작별·도움 요청의 전체 발화를 고정 문구로 처리한다.
- 정해진 표현만 지원한다. 공백과 문장 끝의 마침표·느낌표·물음표·물결표·말줄임표를 정규화한다.
- 문장에 인사나 감사가 포함됐다는 이유로 실제 상담 질문을 생략하지 않는다.

| 입력 예시 | 응답 |
| --- | --- |
| 안녕하세요 / 안녕 / 반갑습니다 | 안녕하세요. 무엇을 도와드릴까요? |
| 감사합니다 / 고마워요 / 고맙습니다 | 천만에요. 더 궁금한 점이 있으면 말씀해 주세요. |
| 안녕히 계세요 / 잘 가요 / 수고하세요 | 이용해 주셔서 감사합니다. 궁금한 점이 생기면 다시 말씀해 주세요. |
| 도움말 / 뭐 물어볼 수 있어요? | 요금제, 청구·납부, 유심, 로밍 등 통신 서비스와 매장 관련 질문을 도와드려요. 궁금한 내용을 말씀해 주세요. |

## 판단과 호출 흐름

- 활성 상담 처리기의 `ConsultTurnAnalysisAdapter`가 실행·메시지·세션 관계를 확인한다.
- `BasicConversationAnalysisProvider`가 기본 대화를 판단한다.
- 대기 질문이 있으면 항상 기존 `QueryRoutingAnalysisProvider`의 후속 처리로 넘긴다.
- 대기가 없고 전체 발화가 지원 표현과 일치하면 `AnalysisResult.direct`를 반환한다.
- 그 외에는 원래 입력과 문맥을 기존 분석기에 그대로 전달한다.
- 기본 응답은 의도 분류 모델·FAQ 검색·RAG 답변 생성 호출을 하지 않는다.
- 기존 대화 요약·제목 생성 등의 저장 후 작업은 그대로 유지한다. 모든 모델 호출을 생략한다는 의미는 아니다.

| 입력·상태 | 처리 |
| --- | --- |
| 대기 없음 + 감사합니다 | 고정 감사 응답 |
| 대기 없음 + 안녕하세요, 유심 비용 알려주세요 | 기존 상담 분석 |
| 대기 없음 + 네 / 아니요 | 기존 분석, 조건 임의 생성 없음 |
| 대기 있음 + 네, 고마워요 | 기존 후속 분석, 대기 조건 문맥 유지 |
| 대기 있음 + 감사합니다 | 기존 후속 처리 우선, 새 기본 응답으로 상담 상태 변경하지 않음 |
| 가입한 달이 무슨 뜻이에요? | 기존 분석, 기본 도움 요청으로 대체하지 않음 |

## 저장·조회·전송 계약

- `persistDirectAnswer`의 기존 저장 계약을 재사용한다.
- 실행과 답변은 `COMPLETED`, 메시지 유형은 `ANSWER`로 저장한다.
- `answerBasis`는 `null`이다. 고정 인사를 FAQ 근거 기반 답변이나 근거 부족으로 분류하지 않는다.
- 기본 응답은 상담 요청이나 사용자 조건을 새로 만들지 않는다.
- 직접 답변의 기존 SSE 계약을 유지한다. 저장 후 `complete`에 실행·출력 메시지 식별자를 전달하며 `token`은 별도로 보내지 않는다.
- 실제 응답 내용은 해당 출력 메시지의 대화 기록 조회 결과로 확인한다.
- 작별 인사는 세션 종료 명령이 아니다. 종료는 기존 API 정책을 따른다.

## 검증 방법과 제약

- 지원 표현과 표기 변형에 대한 고정 응답, 혼합 질문의 위임, 대기 중 입력의 위임을 단위 테스트한다.
- 활성 Chat 처리기·독립 테스트 DB·이력 조회 API·SSE 이벤트 연결로 동일 출력 메시지와 중복 저장 여부를 확인한다.
- 혼합 FAQ 질문과 기존 매장 지역 되묻기 후속 입력이 정상 경로로 이어지는지 확인한다.
- 자동 테스트의 모델·검색 대역은 실제 모델 품질이나 실제 브라우저 동작을 보장하지 않는다.
- 자유로운 잡담·페르소나·자동 후속 질문 추천·욕설 처리·매장 검색 연동은 이 기능의 지원 범위에 포함하지 않는다.
- 기본 인사 답변의 실시간 브라우저 표시와 저장 후 기록 갱신은 기존 화면 소비 계약에서 별도로 확인한다.
