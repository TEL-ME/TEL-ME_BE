- 사람 기준: [용재 직접 판정 39건](20261005-service-pipeline-human-review-lyj.md). 파일 SHA-256은 `11e18dbd43da09653ebaa5a3a244a0f690ca8de76ac3b10e5339366ff1b42c08`이다. 이 판정은 수정하지 않았다.
- 대상 답변은 [2026-10-02 실제 채팅 실행](20261002-service-pipeline-results.md)에 저장된 EXAONE 답변이다. 답변 생성과 검색은 다시 실행하지 않았다.
- 기준 Judge는 [기존 원시 결과](20261002-service-pipeline-judged-raw.json.gz), 수정 Judge는 vLLM 0.29.0의 `Qwen/Qwen3-14B-AWQ`를 동시 작업 8개로 실행한 [새 원시 결과](20261005-human39-judge-updated-raw.json.gz)다.
- 39건 재평가에서는 기존 근거성 정상 출력 25개를 유지하고, 미채점 15개만 다시 판정했다. 질문 충족도와 답변 불가 축은 40개 실행 턴 모두 새로 판정했다. 마지막에는 동일한 모델 응답으로 검토 필요 표시와 집계를 다시 계산했다. 원시 파일에 각 요청과 응답 및 이전 결과의 출처를 남겼다.
- 39건에는 기존 미채점, 사람 확인 필요, 정상 채점 사례를 의도적으로 섞었다. 이 표본의 일치 수치는 서비스 전체 환각률이나 Judge 전체 정확도가 아니다.

## 수정 내용과 해석

1. 질문 충족도는 각 하위 질문을 독립적으로 판정하고, 다른 질문에 관한 문장이나 일반 안내에 부분 점수를 주지 않도록 지시했다. 아직 H-001 등 10건은 사람과 다른 판정이다.
2. 답변 불가 판정의 거절 감지와 근거 충분성 판정을 별도 호출로 분리했다. 근거 판정 호출에는 생성된 답변을 넣지 않는다. 평가 입력의 `qualityReferenceGroups`에서 하위 질문 **문구만** 전달하고 정답 FAQ 내용이나 기대 라벨은 전달하지 않는다. 한 하위 질문이라도 근거가 부족하면 전체 근거를 부족으로 합친다. 충분성 불일치는 7건에서 3건으로 줄었다. 이 하위 질문 분해는 고정 평가 입력에 있는 정보이며 실제 사용자 입력에 자동으로 제공되는 값은 아니다.
3. 주장 추출이 답변 원문을 정확히 복사하지 못한 경우에는 답변의 원문 문장을 그대로 사용해 근거성을 임시 판정한다. 개별 주장으로부터 전체 판정값을 계산해 모델의 집계 오류도 보정한다. 39건 중 11건에 문장 대체 추출, 2건에 전체값 보정이 사용됐다. **문장 대체 추출 11건은 모두 사람 검토 필요로 표시하고 자동 환각률과 자동 품질 통과율에서 제외한다.** 11건의 임시 근거 판정 중 9건이 사람과 같고 2건은 달랐다.

수정 Judge는 39건의 세 평가 축 모두 출력했지만, 문장 대체 추출 11건과 그 밖의 모호한 사례를 포함해 17건은 사람 검토가 필요하다. 근거성 자동 집계에 사용할 수 있는 것은 40개 실행 턴 중 26개다. 39개 표본에는 이전 대화용 선행 턴 1개가 추가되어 평가 실행 턴이 40개다.

## 별도 40건 점검

사람 판정 39건에 포함되지 않은 실행 완료 사례에서 고정 시드 `20261005`로 유형별 40건을 뽑았다. [사례 목록](20261005-heldout40-cases.json), [입력 캡처](20261005-heldout40-capture.json.gz), [새 원시 결과](20261005-heldout40-judge-updated-raw.json.gz)를 보존했다. 40건 모두 세 축의 출력 검증을 통과했고 사람 검토 필요 판정은 0건이었다. 기존 Judge와 비교하면 근거성 최종 라벨은 0건, 질문 충족도는 2건, 답변 불가는 2건 바뀌었다.

이때는 독립된 사람 판정이 없어 출력 검증과 라벨 변경만 확인했다. 이후 [별도 40건 사람 판정본](20261005-heldout40-human-review-lyj.md)을 받았고 [Judge와 대조한 결과](20261005-heldout40-human-judge-comparison.md)를 따로 기록했다. 이 표본도 유형별로 뽑은 고정 평가 질문이며 실제 사용자 분포의 정확도 추정치로 사용하지 않는다.

## 남은 판단 오류

- 근거성: H-001과 H-028은 사람이 `UNSUPPORTED`로 봤지만 Judge가 놓쳤다. H-015, H-018, H-030, H-032는 반대로 사람의 `SUPPORTED`를 `UNSUPPORTED`로 봤다.
- 근거 충분성: H-019, H-025, H-035는 사람이 `ENOUGH`로 봤지만 Judge가 `INSUFFICIENT`로 판단했다.
- 답변 불가: H-026의 복합 질문 거절과 H-039의 엉뚱한 되묻기는 현재 거절 여부와 근거 충분성만으로 정확히 표현되지 않는다.

따라서 수정된 Judge 결과도 사람 판정을 대체하지 않는다. 509건 전체의 기존 자동 점수는 새 Judge로 재계산하지 않았으며 [기존 결과](20261002-service-pipeline-results.md)는 당시 판정 기준의 수치로 유지한다.

## 다음 검증

기존 39건과 겹치지 않는 [별도 40건 검토표](20261005-heldout40-human-review.md)를 사용했다. [사람 판정본](20261005-heldout40-human-review-lyj.md)은 원본 답변과 실제 근거를 보고 작성했고, [대조 보고서](20261005-heldout40-human-judge-comparison.md)에서는 근거성 29/40, 질문 충족도 34/40, 근거 충분성 32/40, 답변 불가 29/40이 일치했다. V6H-012의 외국인 적용 근거가 실제 검색 결과에 없다는 사람 판정을 반영해 근거성 및 답변 불가 일치는 각각 1건 늘었고, 근거 충분성 일치는 1건 줄었다. 유효한 출력 40건과 의미 판단이 맞은 40건은 다르다.

V6H-026은 사람 기준 `MISROUTED_CLARIFICATION`으로 분류됐다. 자동 결과에도 `ROUTING_MISMATCH`가 있으나, 이는 의도 불일치만 감지한 것이고 무관한 되묻기까지 판정한 값은 아니다. V6H-007과 V6H-024의 판정 이유 및 답변 불가 라벨은 실제 RAG 근거와 평가 기준에 맞춰 [사람 판정본](20261005-heldout40-human-review-lyj.md)에 반영했다. 확인 기록은 [재확인 기록](20261005-heldout40-label-review.md)에 남겼다. 남은 오판을 유형별로 고치며, 이 40건을 수정 기준으로 사용한다면 별도의 새 사람 판정 표본으로 다시 검증해야 한다. 509건 전체의 기존 자동 점수는 새 Judge로 재계산하지 않았다.

남은 불일치는 [사례별 분석](20261005-heldout40-disagreement-triage.md)에서 실제 답변과 전달 근거, Judge 이유를 대조했다. 최종 답변 불가 불일치 11건은 모두 근거성 불일치에서 이어졌다. V6H-012는 FAQ 질문 문구를 정책 근거로 보지 않는 기준을 적용해 사람 판정을 갱신했다.
