# TELME-100 LLM Judge 판정 기준 재검증

이 결과는 `develop`의 고정 커밋 `d54964386d5de6db363fb34d205099cd66953ad8`에서 만든 답변과 500건의 합성 검증셋을 사용했다. 최신 `develop`의 채팅 품질이나 실제 환각률을 측정한 결과가 아니다.

## 변경한 판정 방식

- 근거성, 답변 충실도, 답변 불가 신호를 별도 Qwen 요청으로 검사한다. 답변 불가 최종값은 근거 없는 주장이 있으면 `SHOULD_ABSTAIN`, 거절했으나 검색 근거가 충분하면 `OVER_REFUSAL`, 거절했고 근거가 부족하면 `APPROPRIATE`로 계산한다. 근거의 답변 가능성이 불확실하면 `REVIEW`로 남긴다.
- 답변 불가 요청에는 기대 라벨, 정답 FAQ ID, `requiredFacts`, 서버의 `answerBasis`를 보내지 않는다. 충실도 요청에는 질문, 실제 답변, `requiredFacts`만 보내므로 검색 FAQ에만 있는 내용을 답변했다고 세지 않게 했다.
- 근거 없는 `SUPPORTED` 주장에 빈 `sourceIds`를 붙인 결과는 유효한 판정으로 세지 않는다. 근거 판정에서 확인된 조건이 실제로 주장을 뒷받침하는지는 여전히 모델 판단에 의존한다.
- 500건 실행은 동일한 평가셋, 모델 digest, 요청 본문을 검증한 뒤 기존 근거성 499건과 중단된 실행의 답변 불가 신호 144건을 재사용했다. `USIM-0072`의 근거성은 새로 호출했고, 재시도까지 같은 출력 규칙 오류가 나서 미채점으로 보존했다.

## 실제 채팅 기록 9건 재채점

기존 Spring 채팅 API로 생성해 저장한 9개 답변을 다시 Qwen으로 채점했다. 9건 모두 유효한 형식이었다. 기존 사람 판정과의 일치는 근거성 8/9, 충실도 7/9, 답변 불가 8/9다. `NO_EVIDENCE`에서 질문은 택배비 별도 여부인데 답변은 “유심 재발급 비용은 7,700원으로 포함되어 있습니다.”였다. 검색 FAQ에는 재발급 비용만 있고 택배비 포함 여부가 없다. 이번 Judge는 이를 근거 있는 완전 답변으로 보아 세 축 모두 사람 판정과 달랐다. `STORE`의 이용 불가 안내도 충실도에서 `NOT_APPLICABLE`로 보았지만 사람 판정은 `MISSED`다.

## 한계와 검토

500건은 규칙으로 만든 합성 답변이다. 같은 검증셋의 실패를 보며 판정 기준을 수정했으므로 독립 성능 추정에 사용할 수 없다. 충실도의 이전 결과와 이번 결과는 입력과 기준이 달라 단순한 모델 성능 비교도 아니다. 실제 채팅 기록은 9건뿐이다. Qwen은 온도 0에서도 같은 질문에 다른 결과를 냈다. 새로운 독립 질문과 사람 판정을 늘리기 전에는 이 수치로 품질 목표를 확정하지 않는다.

사람이 확인할 우선 사례와 기록 칸은 [검토표](20261001-human-review.md)에 정리했다. 모델 판정과 사람 판정이 충돌한 사례를 먼저 확인한 뒤, 합성 라벨 자체가 잘못된 경우에는 평가셋을 수정하고 기존 결과와 변경안을 동일한 새 기준에서 다시 채점해야 한다.
