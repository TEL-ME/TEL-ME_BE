# 문맥 판정과 이전 발언 연결

## 목적

현재 질문만으로 상담 대상을 알 수 있는지 먼저 판정하고, 대상이 생략된 경우에만 이전 고객 발언에서 대상을 찾아 연결한다. `요금 안 내면 언제 정지되나요?`처럼 혼자 이해되는 질문은 이전 대화가 없다는 이유로 막지 않고, `그럼 비용은 얼마나 드나요?`처럼 대상이 빠진 질문은 이전 업무와 그 정정을 함께 전달한다.

공개 API, DB 스키마와 `application.yml`은 변경하지 않는다. 정상 되묻기 응답의 기존 상담 연결은 유지한다.

## 처리 흐름

| 단계 | 판단 주체 | 처리 |
| --- | --- | --- |
| 호출 후보 선정 | 코드 | 기본 `REGEX_GATED`는 공백과 문장 부호를 무시한 정규식과 아래 일반어 규칙으로 후보를 고른다. 후보가 아니면 원문 그대로 진행한다. `LLM_ALL`은 모든 새 질문을 후보로 본다 |
| 일반어 후속 질문 | 코드 | 문장 전체가 지시어·시점 표현·질문 항목·어미로만 이뤄지면 모델 없이 대상 생략으로 본다 |
| 현재 대상 판정 | 모델 | 위에 해당하지 않으면 현재 문장만 보고 `EXPLICIT`, `OMITTED`, `AMBIGUOUS` 중 하나를 고른다. 이전 주제는 넣지 않는다 |
| 이전 발언 분석 | 모델 | 대상이 생략됐고 이전 고객 발언이 있을 때만 호출한다. 발언마다 새 업무 개수와 정정 연결을 표시한다 |
| 출처 선택 | 코드 | 분석 결과로 참조할 업무를 고르고, 그 업무의 원래 발언부터 최신 정정까지 원문을 순서대로 전달한다 |

`EXPLICIT`이면 원문으로 진행하고 이전 주제를 전달하지 않는다. `AMBIGUOUS`이거나 대상을 하나로 정할 수 없으면 확인 안내를 제공한다. 업무는 명확하지만 FAQ 정답이나 신청 조건이 부족한 경우는 이후 검색과 FAQ 되묻기가 처리한다.

### 일반어 후속 질문 규칙

- 현재 문장을 이루는 낱말이 모두 정해진 목록에 있을 때만 적용한다. 목록은 지시어(`그건`, `그거`), 시점 표현(`그때`, `아까`, `이전에`), 위치 지정(`첫 번째로`), 질문 항목(`비용`, `요금`, `기간`, `방법`, `서류`), 행위(`신청`, `취소`), 어미와 조사로 구성한다.
- 업무 이름이나 상황 낱말이 하나라도 있으면 일치하지 않으므로 모델 판정으로 넘어간다. `요금 너무 많이 나왔어요`, `이심 신청은요?`는 규칙에 걸리지 않는다.
- 규칙은 대상 생략 쪽으로만 판정한다. 이전 고객 발언이 없으면 모델을 부르지 않고 확인 안내로 끝난다.
- 공백 제거 후 30자를 넘는 문장에는 적용하지 않는다.

### 출처와 정정 연결

- 모델은 고객 원문을 복사하거나 새 질문을 만들지 않는다. 이전 발언마다 `index`, `targetCount`, `parentIndex`를 반환한다.
- `index`는 제공한 고객 발언의 순서 번호다. DB 메시지 ID는 모델에 넘기지 않고 검증 후 실제 ID로 연결한다.
- `targetCount`는 그 발언에서 새로 도입한 업무 개수다. 발언 하나에 인터넷 가입과 번호이동이 있으면 2이며 임의로 하나를 고르지 않는다.
- `parentIndex`는 앞선 업무를 이어 묻거나 정정하는 발언의 연결이다. 앞선 업무 발언에만 연결할 수 있고 순환과 미래 참조는 거부한다.
- 모든 출처가 중복 없이 제공되어야 한다. 모델이 반환한 배열 순서와 관계없이 원문 번호로 정렬해 연결한다.
- 참조할 업무는 다음 순서로 정한다.
  1. 현재 문장에 `첫 번째로 물어본`, `두 번째로 문의한`, `처음 물어본` 같은 위치 지정이 있으면 코드가 정정을 제외한 업무 순서로 센다. 모델의 위치 판정은 쓰지 않는다. 해당 순서의 업무가 없으면 확인 안내다.
  2. 위치 지정이 없고 모델이 `referenceScope=RECENT`를 반환하면 가장 최근 업무를 고른다.
  3. 그 밖에는 모델이 지정한 위치를 쓰고, 위치가 없으면 업무가 하나뿐일 때만 그 업무를 쓴다.
- 고른 업무 발언에 대상이 여러 개면 확인 안내를 제공한다.

예를 들어 `유심 재발급을 대리인이 신청합니다` 다음에 `대리인이 아니라 제가 직접 신청합니다`가 있으면 두 원문을 함께 전달한다. 관련 없는 다른 업무와 이전 AI 답변은 전달하지 않는다.

## 검증과 실패 처리

- Ollama 요청은 JSON Schema로 출력 필드, 배열 길이, 번호 범위를 제한한다.
- 코드가 중복, 누락, 숫자 형식, 부모 관계, 고객 원문 여부를 다시 검증한다.
- 잘못된 출력과 호출 실패는 출처 일부만 전달하지 않고 확인 안내로 처리한다.
- 코드가 보장하는 것은 구조, 출처 존재, 연결의 일관성이다. 모델이 판정한 업무 개수나 참조 의미가 정확하다는 보장은 아니다.

## 설정과 기록

- 모드는 `chat.question-resolution.mode`(환경 변수 `CHAT_QUESTION_RESOLUTION_MODE`)로 선택하며 기본값은 `REGEX_GATED`다.
- 두 모델 호출은 `CONTEXT_RESOLUTION` 작업으로 기록하고 프롬프트 버전은 `multiturn-resolution-v30-reference`, `multiturn-resolution-v30-sources`다.
- 현재 대상 판정 출력은 64토큰, 이전 발언 분석 출력은 `min(2048, 128 + 64 × 출처 수)`다. temperature는 0이고 Qwen3와 EXAONE 4.0에서는 이 요청의 사고 모드를 끈다.
- 실행 trace의 `questionResolution`에 최종 관계와 실제 출처 ID를, `questionResolutionEvidence`에 분석 결과, 판정 주체(`referenceSource`: `RULE` 또는 `MODEL`), 순서 번호와 실제 ID의 대응을 남긴다.
- 내부 `EXPLICIT`, `OMITTED`, `AMBIGUOUS`는 처리 결과에 따라 `SELF_CONTAINED`, `HISTORY_DEPENDENT`, `CLARIFICATION_REQUIRED`로 기록한다.

## 한계

- 일반어 규칙에 걸리지 않는 문장의 대상 유무는 모델이 판정한다. 대상이 생략된 문장을 `EXPLICIT`로 판정하면 이전 업무 없이 진행한다.
- 기본 모드에서 지시어·시점 표현·질문 항목이 없는 생략형 후속 질문(`미국은요?`, `가족도 되나요?`)은 후보가 아니어서 독립 질문으로 처리한다. `LLM_ALL`은 후보 검사를 생략할 뿐 판정 방식은 같다.
- 가장 최근 업무를 고르는 규칙 때문에 이전 업무가 여러 개일 때 `그건 얼마예요?`는 확인 안내가 아니라 최근 업무로 연결된다.
- 같은 뜻의 문장이라도 띄어쓰기에 따라 모델 판정이 달라질 수 있다.

## 평가 재실행

실제 모델과 API 호출은 `ContextResolutionLiveEvaluationTest`가 수행한다. 평가 입력은 [cases.json](../scripts/context-resolution-evaluation/cases.json)에 기대 관계와 필요한 이전 발언 번호로 고정한다. 관계와 출처가 모두 맞아야 일치로 센다. 질문의 최종 답변 정확도와는 별개다.

- `RUN_TELME139_LIVE=true`일 때만 실행한다. 개발 DB를 쓰지 않도록 DB 이름이 `telme_139_`로 시작하는지 확인한다.
- 빈 평가 DB에 스키마를 적용한 뒤 `prepare_database.py --source <FAQ가 있는 DB> --target <평가 DB>`로 FAQ와 임베딩만 복사한다. 데이터가 있는 대상 DB에는 복사하지 않는다.
- `TELME139_FIXTURE_KEY`로 `cases.json`의 입력 묶음을 고르고, 실행마다 새 `TELME139_RUN` 값을 쓴다.
- `summarize.py`가 원시 결과를 집계한다. 결과는 `scripts/context-resolution-evaluation/runs/`에 생성되며 저장소에 포함하지 않는다.
- `cases.json`의 일부 현재 질문은 프롬프트 예시와 같은 문장이다. 프롬프트에 없는 문장으로 측정한 결과와 구분해서 해석한다.

```powershell
$env:POSTGRES_DB = '<telme_139_로 시작하는 평가 DB>'
$env:SPRING_FLYWAY_LOCATIONS = 'classpath:db/migration'
$env:RUN_TELME139_LIVE = 'true'
$env:TELME139_RUN = '<새 실행 이름>'
$env:TELME139_FIXTURE_KEY = 'cases'
./gradlew.bat test --tests '*ContextResolutionLiveEvaluationTest' --rerun-tasks
```
