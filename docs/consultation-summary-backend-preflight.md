# 상담 요약 백엔드 최종 점검

문의별로 답변 원문을 묶고 남은 사항은 저장 상태로 구분하는 백엔드 구현을 점검했다. 프론트 구현은 이번 PR 범위에서 제외한다.

## 최신 코드와 추가 보완

- 기준: `origin/develop`의 `ef23b28a`까지 반영했다. Bedrock 판정기 적용과 겹치는 `FaqSearchAnswerProvider`에는 양쪽 변경을 함께 유지했다.
- 긴 동일 유심 문의의 문맥 복원, 복원 질문 기준 재검색 후보 검증, 근거 없는 신청 권유 제거를 포함한다.
- 다른 사람·회선에 같은 답변을 해도 출처별로 나누며, 가족 기간의 주체를 임의로 바꾸지 않는다. A회선·회선 A와 순번·숫자 호칭은 같은 대상으로 확인한다.
- 추가 점검에서 원문 전달 경로가 안내 불가 문구도 `GROUNDED`로 고정하던 반례를 재현했다. 검사 후 답변에 따라 `NO_EVIDENCE`를 반환하도록 보완하고 회귀 테스트를 추가했다.

## 최종 검증

| 단계 | 결과 | 범위 |
| --- | --- | --- |
| 자동 테스트 완료 | 관련 821개 통과, 실패·오류·생략 0개 | 모델·판정기 대역, 화면용 DB와 분리한 테스트 DB |
| 빌드 완료 | `bootJar` 성공 | 최신 develop과 로컬 변경 포함 |
| 실제 로컬 모델 검증 완료 | 고정 상담 26개, 기존 정답 기준 69개 보존 | `exaone3.5:7.8b`, 기존 최종 결과와 동일. 모델이 안내 번호를 선택하고 서버가 원문 중심으로 구성 |
| 실제 백엔드 HTTP 검증 완료 | 유심 상담 2회 질의 → 종료 → 요약 재조회 성공 | 새 게스트·로컬 FAQ, 프론트 미사용. 한 문의·중복 제거·18개월·비용·조건·방문·미접수 상태 보존 |
| 개인정보 검사 | 167단계에서 지원 민감번호·합성 원번호·구분 가능한 끝자리 노출 0건 | 모델 입력·원출력·요약·HTTP 응답. 양성 대조 2개 검출. 검사 스크립트 보정 전 실행도 포함 |
| 프론트 보존 | 소스·설정 등 450개 파일 동일 | 이번 점검에서 수정·실행하지 않음 |

최신 develop은 회색 구간과 Bedrock 판정기를 기본으로 사용한다. **이번 실제 HTTP 검증은 유료 호출을 막기 위해 두 설정을 껐다.** 최신 판정기 경로는 자동 테스트에서 대역으로 확인했으며, 실제 Bedrock과 결합한 상담 결과를 검증한 것은 아니다. 원격 CI도 아직 실행하지 않았다.

원답변이 틀리면 원문 중심 요약에도 남을 수 있다. 69개 고정 기준 보존과 지원 번호 검사 결과를 전체 사실성·모든 개인정보 유형의 보장으로 확대하지 않는다.

## 응답과 PR 범위

- 기존 `summary.topics`, `guidance`, `pendingItems`는 유지한다.
- `summary.inquiries`: 문의별 `title`, `text`를 추가한다.
- `summary.remaining`: 남은 사항의 `title`, `text`, `kind`를 추가한다. `kind`는 `NEEDS_CONFIRMATION`, `UNANSWERED`, `OUT_OF_SCOPE`, `INTERRUPTED`, `WAITING_RESPONSE`다.
- 새 HTTP API·DB 테이블·Flyway 마이그레이션은 없다. 공통 응답 DTO의 필드 추가는 프론트 담당자와 합의해야 한다.
- 문맥·라우팅·검색·RAG 변경은 해당 담당자 리뷰가 필요하다. 진행 중인 PR #156과 `ChatQuestionResolver`가 겹치므로 병합 전에 다시 대조한다.
- 구현·관련 테스트·이 문서·이전 비교 근거만 PR 포함 후보로 정리했다. 프론트 소스, 실행 JAR, 모델 원출력, 합성 원번호 자료, 로컬 서버 파일은 포함하지 않는다.
- 커밋·푸시·PR 생성은 하지 않았다. 기존 문서·사진·실험 결과는 그대로 보존했다.
