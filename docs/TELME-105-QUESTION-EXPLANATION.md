# TELME-105 되묻기 질문 설명과 기존 상담 재개

## 기준과 범위

Jira: [TELME-105](https://telme-team.atlassian.net/browse/TELME-105). 실제 Jira에서 이슈 키·제목·가입월/이번 달 변경 이력 범위를 확인했다. 이슈 키 기재와 개발 패널의 자동 연결 확인은 별도 결과다.

작업 시작 시 104 게시 작업본은 미커밋 변경 없이 `d7842ee726851df4064f2a2d979cc3cf2eb6b83d`였다. 98 PR #87과 104 PR #88은 OPEN이었다. 원격 105 브랜치·PR은 없었다. 별도 `fix/TELME-105-plan-question-explanation`을 #88 HEAD에서 만들고 PR 비교 기준을 `fix/TELME-104-followup-context`로 둔다. 104 원본 브랜치에서 직접 수정하지 않는다. 98·104의 변경 이력은 선행 기반이며 105 diff에 포함하지 않는다. 선행 병합 후 develop 기준으로 분리·재검증해야 한다. 자동 병합은 하지 않는다.

저장소 PR 양식의 작업 내용·Jira·변경 사항·리뷰 포인트·참고 사항을 사용한다. 별도의 브랜치/커밋 규칙 파일은 발견하지 못했으며 기존 이슈 키가 포함된 브랜치·커밋 관례를 따랐다. 요청된 `architecture.md`, `requirements.md`, `rag-pipeline.md`, `decisions.md`는 현재 저장소에 없다. 기존 상담 검증 문서, `POLICY.md`, 활성 코드와 CI를 확인했다.

가입월·이번 달 변경 이력 질문의 뜻을 설명하는 범위다. 일반 정책 질의·정정·거절·모름·보류·새 질문의 기존 처리는 유지하며 상담 유형·모델·프롬프트·검색·Guard·평가 기준·스키마를 변경하지 않는다. 부분 조건 응답과 설명 요청이 섞인 복합 발화를 새로 지원하지 않는다.

## 기존 문제와 처리 흐름

104는 `가입한 달이 무슨 뜻이에요?`를 DEFERRED로 해석해 원래 질문을 유지하지만 설명 메시지는 저장·전송하지 않는다. 104의 기존 실제 모델 EXPLAIN 사례와 자동 통합 테스트에서 확인한 동작이다.

활성 경로는 `Chat → ConsultChatProcessingService → ConsultTurnAnalysisAdapter → 소유권/실행 연결을 확인한 FollowupContextService`다. 설명 요청에서는 하나의 FAQ 요금제 대기 후보를 확인하고 `PlanChangeQuestionExplanation`이 기존 104의 설명 요청 판별·조건 추출을 재사용한다. 조건 응답이나 새 요청이면 기존 분석·후속 검증으로 넘긴다. 설명은 별도의 모델 호출 없이 정해진 안내문으로 제공한다.

설명 내용:

- 가입한 달은 가입 날짜가 속한 달력상의 달이다. 가입일부터 한 달이 지났는지를 묻는 것이 아니라 이번 달에 가입했는지 확인한다.
- 변경 이력은 요금제를 바꾼 적이 있는지를 뜻한다. 이번 달에 이미 바꾼 적이 있는지 확인한다.
- 안내문 뒤에 기존 대기 질문을 덧붙인다. 새 CLARIFICATION 메시지는 만들지 않는다.

달력상 가입월 의미는 기존 `PlanChangeClarificationPolicy.generationGuidance`와 [서비스 정책 BILLING-01](POLICY.md)·TELME-98의 가입월/월별 변경 기준을 따른다. 고객의 가입일이나 변경 이력은 추정하지 않으며 개인별 가능·불가, 새로운 기간·비용·제한을 설명에 넣지 않는다. 질문 용어 설명에는 FAQ grounded 판정을 부여하지 않는다.

## 저장·대기·전송 계약

일반 `completeAnswer`는 세션을 OPEN으로 재개하므로 설명에 그대로 쓰면 대기가 해제된다. `completeAnswerWhileWaiting`은 동일한 메시지·실행 완료 기능을 사용하면서 세션의 NEED_CLARIFICATION을 유지한다. `ConsultChatPersistenceService.persistWaiting`의 설명용 오버로드가 기존 실행·세션·완료된 질문·PENDING 조건·WAITING_CONDITION 상담 연결을 재검증한다. 오래된 질문이나 다른 세션의 질문이면 같은 트랜잭션에서 설명 저장과 상태 변경을 롤백한다.

| 항목 | 설명 후 상태 |
| --- | --- |
| 이번 chat_execution | COMPLETED, 설명 output_message_id 연결 |
| 설명 chat_message | ANSWER/COMPLETED, reply_to는 이번 설명 요청 입력 |
| 상담 consult_request | 기존 ID·WAITING_CONDITION·version 유지 |
| 대기 조건 | 기존 key·PENDING·값 없음·asked_message_id 유지 |
| 이미 확인한 조건 | 기존 값·상태·응답 연결 유지 |
| 세션 | NEED_CLARIFICATION 유지 |
| 다음 후속 응답 | 같은 상담·원래 질문의 조건으로 반영 |

설명 메시지는 기존 직접 안내와 동일한 `complete` 이벤트/메타데이터 계약을 사용한다. 설명에 start/token 이벤트를 추가하지 않는다. complete의 outputMessage ID로 기록 API에서 같은 설명을 조회한다. 이후 최종 생성 답변은 기존 Guard → 저장 → SSE start/token/complete 흐름을 유지한다.

실행 trace의 analysis에는 `WAITING_EXPLANATION`과 `pendingQuestionMessageId`를 남겨 원래 질문을 연결한다. Guard 전 원문 로그나 중복 추적 테이블은 추가하지 않는다.

설명 실행에는 출력 메시지가 있으므로 기존 미해결 응답 집계(`COMPLETED`이며 출력 없는 실행)에서 제외된다. 설명 요청이 반복 종료 횟수를 소비하지 않는다. 동일 조건의 해석 불가 응답 2회 정책은 바꾸지 않았다.

## 대화 예시와 검증

1. “제가 지금 요금제를 바꿀 수 있나요?” → “이번 달에 가입하셨나요?”
2. “가입한 달이 무슨 뜻이에요?” → 달력상 가입월 설명 + 원래 질문. 조건은 채우지 않고 기존 상담 대기 유지.
3. “지난달이요” → 원래 가입월 조건에 아니요 저장, 이번 달 변경 이력 질문.
4. “그 질문 뜻이 뭐예요?” → 변경 이력 설명 + 원래 질문. 가입월 아니요 유지.
5. “아니요” → 같은 상담의 변경 이력에 아니요 저장, 기존 FAQ·Guard 경로로 최종 답변 후 DONE.

자동 검증은 실제 활성 Chat 처리기·후속 입력·PostgreSQL·저장·기록 조회 API·SSE registry를 통과한다. 외부 모델과 검색만 대체한다. 검증 목록:

- 구체적인 가입월/변경 이력 표현과 대기 질문 문맥의 “무슨 뜻이에요?”, “질문이 무슨 뜻이에요?”
- 설명 전후의 상담 ID·version·조건값·asked/answered 메시지 ID 보존
- 설명 후 짧은 응답·최신 가입월 정정·최종 답변 재개
- 설명 3회 후에도 해석 불가 응답 횟수를 소비하지 않음
- 새 질문 전환 시 원래 상담 취소 및 조건 복사 없음
- 다른 세션/완료된 상담의 대기 질문으로 설명 저장 시 롤백
- 일반 기준·거절·모름·보류·매장 되묻기·Guard·최종 저장·전송의 기존 회귀

최종 전체 build는 전용 PostgreSQL/PostGIS/pgvector와 JDK 21, `TELME_DB_TESTS=true`에서 **1,497건 중 통과 1,495건, 실패·오류 0건, 평가 프로브 스킵 2건**이다. 설명 단위 23건·활성 Chat 통합 68건·분석 어댑터 7건, 기존 Guard·저장·조회·전송 회귀를 포함한다. 신규 사례는 설명 단위 23건·Chat 통합 15건·어댑터 1건이며 104 사례는 재사용한다. 실행별 테스트 건수와 소스 지문은 [공유 검증 자료](evidence/telme105-question-explanation.json)에 기록했다. 과거 선택 회귀 150건은 최종 표현·어댑터 보강 이전 실행이므로 전체와 합산하지 않는다. 테스트 입력 작성 중 존재하지 않는 완료 메시지 컬럼을 가정한 조회와 매장 조건 fixture를 바로잡았다. 이들은 테스트 구성 문제이며 DB 장애나 제품 코드 결함으로 해석하지 않는다.

## 남은 확인

- 실제 모델로 후속 분류·최종 생성까지 재실행하지 않았다. 자동 테스트의 모델/검색 대체와 실제 모델 품질을 구분한다. 설명 자체는 모델을 호출하지 않는 고정 문구다.
- 팀 실제 화면·브라우저 새로고침은 미검증이며 담당자와 별도로 확인한다. 백엔드 자동 테스트 통과를 실제 화면 검증 완료로 표현하지 않는다.
- 운영 배포·V18/V19 선행 배포 순서는 이번 범위가 아니다. 105에서 마이그레이션을 수정하거나 추가하지 않았다.
- CI pull_request 필터에 정확한 104 브랜치를 추가해 105의 선행 비교 기준에서도 기존 build·마이그레이션 검사·테스트 게시가 실행되게 한다. 선행 CI와 105 최신 HEAD CI는 구분한다.
- 설명 안내문·반복 종료 기준을 별도 정책 문서로 확정할 필요가 생기면 팀과 결정한다. 현재 반복 횟수와 조건 정책은 유지한다.
