# TELME-190: Answer Guard 가격 비교 원문 복구

## 배경과 변경

FAQ 177의 답변은 `일주일이면 7일 기간권 39,000원이 가장 유리합니다.`라고 안내한다. 모델이 이를 `7일 기간권이 39,000원으로 가장 저렴합니다.`로 표현하면 기존 비교 가드는 `가장 저렴`을 근거에 없는 비교로 판단해 문장을 삭제한다.

이 변경은 비교 표현을 폭넓게 허용하지 않고, 조건이 확인되는 경우 FAQ 답변의 원문으로 교체한다. 근거 전체 문법, 고객 질문의 기간, 답변과 근거의 상품·기간·금액을 확인한다. 외부 적용 조건이나 정정 등 해석할 수 없는 내용이 있으면 복구하지 않고 기존 보류 경로를 유지한다. 숫자 검증과 다른 정책 검증은 교체된 문장에도 계속 적용된다.

- 사실 검증 근거는 기존 FAQ 답변(A)이다. FAQ 질문(Q)을 근거에 추가하지 않는다.
- 질문의 날짜·부정·상품 제외·기간 변경을 단순한 일수 일치로 허용하지 않는다. 지원하는 긍정 기간 문법 전체와 일치해야 한다.
- 일반 어순, 가격 먼저 제시하는 어순, 가격을 뒤에서 설명하는 어순을 처리한다.
- 복구 입력은 정규화 전에 문장 512자, 근거 2,048자, 질문 256자로 제한한다. 초과 시 복구하지 않는다.
- 추가 모델/API 호출, public 인터페이스/DTO/DB 스키마 변경은 없다.

## 커밋 구성과 리뷰 순서

1. **구현과 기본 동작**: `AnswerGuard.java` → `ComparisonPriceRecovery.java` → `AnswerGuardRecoveryBehaviorTest.java`. 정상 복구·다른 기간 거절·근거 없는 속도 비교 차단·원문만 있는 경우를 기본 테스트로 유지한다.
2. **핸드오프**: 이 문서. 대규모 검증 결과와 지원 범위, 남은 한계를 정리한다.

대규모 경계/저장 답변 테스트셋과 이에 의존하는 테스트 클래스·실행 설정은 개인 로컬 전용으로 보관한다. 제출 브랜치의 커밋과 기본 테스트에는 포함하지 않는다. 원본은 저장소 밖에 있고, 개인 클론에서 Git이 무시하는 `.local/answer-guard-recovery` 경로로 연결한다. ignore 설정은 커밋되지 않는 `.git/info/exclude`를 사용한다.

기존 실험 브랜치의 최종 구현과 클래스 이름을 제외한 내용이 같은지 확인했다. 제출 브랜치는 `develop`의 `379ac076cb45b028ffbfc593b0a2fc696a359c23`에서 생성했다. 과거 비교/생성 원시 자료와 불채택 구현은 실험 브랜치에 보존하고 제출 diff에서 제외했다.

## 검증

Java 21.0.12.1과 Gradle offline으로 검증했다. 아래 대규모 검증 수치는 로컬 전용 테스트셋을 명시적으로 추가해 실행한 결과이며, 공유 기본 테스트의 의무 조건이 아니다. LlmClient와 관련성 판정은 mock/fake이며, 실제 API 호출은 하지 않았다. `.env`를 읽거나 로드하지 않았다.

| 범위 | 결과 |
| --- | --- |
| 선택한 관련 단위 회귀 | 1,568개, 실패/오류/skip 0 |
| 빌드 | assemble 통과 |
| 추가 안전·복구 계약 | 정상 20개 모두 원문 복구, 위험 93개 모두 차단 |
| 기존 경계 fixture | 48개: 정상 15개, 위험 28개, 부분 안내만 가능한 5개 |
| 기존 저장 출력 fixture | 651개, 기준선 출력과 예외 동일 |
| 실제 생성기 전달 경로 | mock 호출 1회, 최종 답변과 전달 토큰이 기대 원문과 일치 |
| 저장 생성 답변 재생 | 1,668개, 검토 완료한 보완 recovery와 최종 답변 모두 동일 |
| 긴 입력 | 최대 100만 공백을 포함한 복구 요청 거절, 2초 제한 테스트 통과 |

기본 동작 테스트 실행(로컬 데이터 불필요):

```sh
./gradlew --offline test --tests '*AnswerGuardRecoveryBehaviorTest' assemble
```

개인 로컬 검증 실행(선택):

```sh
./gradlew --offline --max-workers=2 \
  -I .local/answer-guard-recovery/regression.init.gradle test assemble
```

위 로컬 경로는 개인 클론에만 있으며 새 클론에는 없다. 저장소 밖 원본은 `git reset --hard`의 대상이 아니다. 로컬 연결을 삭제해도 원본은 남지만, 그때는 연결을 다시 만들어야 실행할 수 있다.

추가 fixture의 113개는 이전 리뷰 47개와 적용 조건/질문/기간 표현을 변형한 66개다. 독립 사람이 작성한 맹검 평가나 운영 오류율 측정이 아니다. 과거 경계 51개 중 이미 알고 있던 별도 가드 결함 `LEGACY_INVALID` 3개는 통과하는 테스트처럼 포함하지 않고 로컬 fixture에서 제외했다. 제출 브랜치의 변경으로 해당 결함이 해결됐다는 의미는 아니다.

## 선택 근거와 자체 리뷰

기존 동의어 통합과 고객 질문 비교 허용은 주장 대상과 적용 조건을 확인하지 않아 추가 반례를 허용했다. FAQ 질문을 근거에 넣는 방식은 다른 금액·기간·채널 검증까지 영향을 주었다. 가격 관계만 확인하는 방식도 앞뒤의 적용 조건을 놓칠 수 있었다. 최종안은 사실 판정 범위를 유지하며 출처의 주장 강도 그대로 복구한다.

자체 리뷰에서 부분 문장만 뽑을 때의 조건 유실, 날짜/부정 의도 오인, 긴 공백 정규식 비용, 정상 복구 assertion 공백을 보완했다. 최종 제출 구현의 내용 동등성과 mock 재생까지 확인했으며 추가 필수 수정 사항은 발견하지 못했다.

## 남은 한계와 운영 반영 전 확인

- **보수적 차단의 대가**: 부분 안내만 가능한 기존 5개 중 4개는 이제 보류한다. 무해한 매장 안내도 근거 전체 문법 밖이면 차단될 수 있다. 최종 저장 생성 답변 1,668개에서는 기존 보완안 대비 손실이 관측되지 않았다.
- **지원 범위**: 문법 밖 정상 질문이나 여러 FAQ가 결합된 근거는 복구되지 않을 수 있다. 조사 없는 `7일 로밍`의 날짜/기간 중의성도 완전히 해소하지 못한다.
- **기존 별도 결함**: 환불 계좌의 본인/가족 교체, 비교 대상 상품 교체 등 기존 가드의 사실/대상 검증 빈틈은 이번 수정 범위 밖이다.
- **직접 확인 필요**: 구현을 보지 않은 사람이 만든 신규 질문과 스테이징의 실제 검색·분해·라우팅·여러 FAQ 조합에서 보류율을 확인한다. 이 문서의 결과는 실서버/DB/부하 검증이나 독립 사람 채점 결과가 아니다.

DB 변경과 외부 부작용이 없어 해당 구현 커밋을 되돌리면 기존 가드 경로로 복구할 수 있다. push와 병합은 수행하지 않았다.
