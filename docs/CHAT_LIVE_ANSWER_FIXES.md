# TELME-206 실시간 답변 품질 개선

## 배경

종료 요약 평가(2026-10-19~20)에서 상담 중 챗봇 답이 이미 질문과 맞지 않은 사례가 나왔다. 요약이 틀린 것이 아니라 실시간 경로의 문제다. 사례와 대화 원문은 `item9-live-answer-cases`(develop `157e924e` 기준)에 있다. 이 문서는 수정 내용과 검증 결과만 담는다.

## 원인과 수정

| 사례 | 원인 | 수정 |
| --- | --- | --- |
| T15 "5G 요금제로 바꾸고 싶은데 뭐 있어요"에 변경 방법만 답함 | 요금제 업무 분류가 "뭐 있어요"를 고르는 말로 보지 않아 변경 요청(`CHANGE`)으로 가로챔 | `PlanTaskRules`의 고르는 중 패턴에 `뭐있`, `어떤 게`, `무슨 것` 추가 |
| T03 로밍 하루 요금에 국내 요금제 목록으로 답함 | 요금제 분류가 "요금", "얼마"만 보고 요금제 목록(`PLAN_CATALOG`)으로 분류 | `PlanQuestionRules`: 요금제·제공량 말 없이 하루 단위 요금을 물으면 요금제 표 대신 FAQ로 보냄 |
| S21 "매장 찾아주세요", S26 "컬러링 해지는 어디서해요"를 범위 밖으로 처리 | 라우팅 모델이 UNKNOWN으로 분류하고 FAQ 검색 재확인도 못 살림 | `QueryRoutingService`: UNKNOWN이어도 매장 찾기 요청이면 STORE로, 컬러링·통화연결음·벨소리·데이터쉐어링과 업무를 함께 물으면 앞 잡담을 떼고 FAQ로 보정 |
| T10 "아 정정할게요 중학생 아니고 초6"를 범위 밖으로 처리 | 정정 말에는 업무 이름이 없어 문맥 해석 후보에서 빠지고 단독 질문으로 라우팅됨 | `ChatQuestionResolver`: 정정 말이 있고 앞 대화가 있으면 문맥 해석 모델이 판정 |
| S28 되묻는 중 "…그리고 분당 서현역 근처 매장도"에서 매장 요청이 사라짐 | 후속 분석 모델이 발화 전체를 되묻기 조건 답으로 판정하고 매장 요청은 값에서 잘림 | `QueryRoutingService`: 매장을 묻는 중이 아닌데 답과 함께 매장 찾기 요청이 있으면 새 질문으로 다시 처리 |
| T16 매장 되묻기 중 "거기 토요일에도 열어?"에 같은 업무 되묻기를 반복 (S19 "홍대입구역 근처 매장 몇시까지해요?"도 같은 증상) | 영업일·영업시간만 물어도 매장 검색에 필요한 업무(번호이동 등)를 되물음 | `QueryRoutingService`: 매장 질문이 영업·운영·몇 시·휴무·주차·전화번호만 묻고 업무 표현이 없으면 업무를 업무 필터 없음(`UNDECIDED`)으로 표시해 되묻지 않음 |
| 영화·노트북 추천이 요금제 추천으로 감 | 분류 모델이 RECOMMENDATION이라 답하면 막을 장치가 없음 | `PlanQuestionClassifier`: 요금제를 고르는 말이 없으면 NONE |

영화·노트북 추천은 실제 모델(gpt-oss)이 이미 막고 있어 지금은 재현되지 않는다. 모델이 틀렸을 때를 위한 방어다.

## 검증 방법

- 단위 테스트와 규칙 분류 전후 비교: FAQ 1,150개와 대화 발화 등 1,523문장.
- 실제 Bedrock(gpt-oss-120b) 비교:
  - 요금제 분류기 51문장. develop과 수정 후 모두.
  - 후속 분석 25문장. develop 2회, 수정 후 1회.
  - 시나리오 60개(148턴) 전체 대화. develop 3회, 수정 후 2회.
  - 의심 사례(T02, T12)는 같은 시나리오를 6~8회 반복.
- T16(S19 포함) 수정은 단위 테스트로만 확인했고 실제 모델로는 돌리지 않았다. 아래 실제 모델 결과는 이 수정 전에 측정한 것이다.
- 수정 코드가 실제로 발동한 턴은 앱 로그와 실행 기록(`pipeline_trace`)으로 따로 확인했다.
- 같은 develop 코드를 두 번 돌려도 148턴 중 16턴은 답 유형이 달라진다. 그래서 develop을 여러 번 돌려 흔들림 범위를 먼저 잰 뒤 비교했다.

## 구조상 줄일 수는 있어도 없앨 수 없는 것

- 모델 답이 매번 흔들린다. 한두 번의 실행으로는 작은 변화를 확정할 수 없어, 프롬프트를 고칠 때는 develop을 3회 이상 돌려 비교한다.
- 정정 말이 있으면 문맥 해석 호출이 한 번 늘어난다.

## 비용

두 차례 검증에 쓴 Bedrock 호출은 약 4,400회다. 토큰 수를 기록하지 못해 문서 단가(gpt-oss-120b 입력 $0.18, 출력 $0.73 / 100만 토큰)로 추정하면 약 $1~1.5다. 실제 청구액은 확인하지 않았다.
