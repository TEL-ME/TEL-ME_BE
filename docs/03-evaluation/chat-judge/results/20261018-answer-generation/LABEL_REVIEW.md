# 답변 생성 채점 라벨 검토 (1차, 이용재)

`labels/human-review.json`의 1순위 18건을 검토했다. 함께 본 것은 명의변경 대리 서류 충돌 건과, 검토하다 같은 문제로 드러난 A 6건이다. 카탈로그(`faq_full_1150.json`)의 answer 본문과 생성에 넘긴 근거를 직접 대조했다. 아래 판단을 라벨(`labels-A.jsonl`, `labels-B.jsonl`)에 반영하고 바뀐 턴만 다시 판정했다(맨 아래 "반영 결과"). 검토한 id와 판단은 `labels/human-reviewed.json`에 있다.

A에서 답할 수 있다고 라벨을 단 입력 중 넘긴 근거가 라벨 근거에 하나도 없는 것은 10개였고, 모두 이 검토에 들어 있다.

## 판단 원칙

- **A는 생성에 넘긴 근거를 기준으로 본다.** A는 근거를 고정해 답변 생성만 보는 시험이다.
  - holdout90은 관련은 있지만 답이 아닌 FAQ를, answer_quality_20은 일부만 답하는 FAQ를 일부러 준다. 여기서 볼 것은 "근거에 없으면 지어내지 않는가"다.
  - 넘기지 않은 다른 FAQ에 답이 있다고 ANSWER로 두면, 근거만 보고 맞게 거절한 답이 실패로 잡힌다. 시험이 뒤집힌다.
  - 그래서 A에서는 카탈로그에 답이 있어도 넘긴 근거에 없으면 답할 수 없는 것으로 본다.
- **B는 카탈로그 기준을 유지한다.** B는 검색까지 거친 실제 경로라 검색이 놓친 것도 시스템의 실패다. TELME-180 서비스 평가와 같다.
- **앱 규칙과 어긋나는 라벨은 앱 규칙을 따른다.**
  - 답변 프롬프트 4번 규칙: 근거 숫자를 더하거나 곱하지 않는다.
  - 답변 프롬프트 6번 규칙: 고객 조건을 모르면 조건을 나누어 모두 안내한다.
- **고객이 묻지 않은 것을 "확인할 수 없다"고 말하도록 요구하지 않는다.** PARTIAL_ANSWER는 답이 없는 부분을 명시적으로 보류해야 통과하므로, 고객이 실제로 물은 부분에만 쓴다.

## 명의변경 대리 서류

- 위임장을 말하는 FAQ 51개 중 49개는 "한쪽이 못 오면 위임장"이라고만 한다. NAME_CHANGE-0001과 0067만 "위임장과 인감증명서"라고 한다.
- 라벨 5건(RU-116, RU-132, RU-276, RU-291, EVAL-148)은 이미 다수 쪽인 "위임장"만 필수 사실로 두었다. 바꾸지 않는다.
- 인감증명서까지 말한 답은 넘긴 근거에 NAME_CHANGE-0001이 있을 때만 근거가 있다. A의 EVAL-148이 그런 경우다. B의 네 건은 NAME_CHANGE-0007만 넘겼다.
- 카탈로그 자체의 불일치라 FAQ 데이터에서 정리할 일로 남긴다. 같은 종류로 법인 개통 신분증(SUBSCRIBE-0089 대 0049·0129)도 있다.

라벨 18개 입력을 고쳤다(A 15, B 3). 고치기 전 라벨로 Judge 입력을 다시 만들면 저장된 입력과 같았고, 고친 뒤 판정 입력이 바뀐 턴은 47개(A 35, B 12)다. 이 턴만 세 Judge로 다시 판정하고 나머지는 저장된 판정을 썼다(`--prior`). 호출 678건, 실패 0, 비용 $0.36.
