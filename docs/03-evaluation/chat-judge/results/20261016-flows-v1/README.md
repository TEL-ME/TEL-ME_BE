# 2026-10-16 흐름 평가셋 v1: 되묻기·매장 찾기·로그인 회원

> 이후 측정: 되묻기 두 갈래 정답과 추천 규칙 근거를 넣은 뒤의 흐름 평가셋 수치는 [2026-10-17 라벨 수정 후 재판정](../20261017-label-fixes/README.md)에 있다. 이 문서의 수치는 그 전 기준이다.

[흐름 평가셋 v1](../../README.md#평가셋)을 실제 채팅 API로 실행했다. 앱이 조건을 되물으면 평가셋에 적힌 고객 답변을 보내 최종 응답까지 받고, 그 응답을 Bedrock Judge 세 모델로 판정했다.

- 실행: 코드 7d8d654e(+이 폴더를 만든 작업 트리), 답변 생성 EXAONE 3.5 7.8B(Ollama), 평가 DB `telme_judge_eval`(telme-flow-postgres). 앱 쪽 Bedrock 호출을 막으려고 회색 구간 근거 판정은 껐다(`appConfig`에 기록).
- 지명 매장: 지명으로 찾는 매장 4개(SF09–SF12)는 첫 실행 때 카카오 로컬 API 키가 없어 빠졌고, 키를 설정한 뒤 같은 코드로 따로 캡처해 합쳤다(`kakaoCasesFrom`). 그 캡처는 전체 대화를 돌리다 15번째에서 중단됐고, 앞에 있던 지명 매장 4개만 썼다. 36개 대화, 38턴이다.
- 회원: 프로브가 테스트 회원(`judge-member@telme.test`, 5G 스탠다드, 24개월 약정 8개월 차)으로 대화하고 대화 직전 계정 데이터를 근거로 남겼다. 첫 실행 뒤 추천이 쓰는 지난 달 평균 사용량(`usageDemand`)을 계정 데이터에 더해 회원 시나리오만 다시 캡처하고 다시 판정했다. 근거의 UTC 시각과 MB 값에는 앱과 같은 한국 시간과 GB 환산을 함께 적었다.
- 비용: Qwen $0.09, DeepSeek(오레곤) $0.22, Mistral $0.22(회원 재실행과 지명 매장 포함).

## 드러난 앱 문제

- **매장 찾기는 지명으로 답한 2개만 통과했다.** 현재 위치로 답한 8개는 모두 실패했다.
  - SF02, SF03, SF04, SF06은 지역을 '현재 위치 사용'(좌표)으로 답했는데, 업무를 답하자 지역을 다시 물었다. 좌표가 버튼을 누른 요청에만 실려 다음 턴에서 위치를 잃는 것으로 보인다. 고객이 위치를 한 번 더 보내야 매장 목록이 나왔다(`REASKED_CONDITION`).
  - 질문에 업무를 말해도("새로 하나 개통", "유심 깨짐") 업무를 다시 물었다.
  - SF05의 "딱히 정해진 업무는 없어요"는 이해하지 못했고, SF07은 지역·업무를 반복해 물으며 끝나지 않았다.
  - SF01, SF08은 매장 질문을 FAQ로 분류해 "관련 안내 정보를 찾지 못했습니다"로 답했다.
  - 지명: SF09(강남역, 신규가입)와 SF11(대전 중구청, 명의변경)은 통과했다. SF10은 "여의도 쪽"을 여의도동 행정구역 하나로만 찾아 "조건에 맞는 매장을 찾지 못했어요"라고 답했다. 평가 DB에는 1~2km 떨어진 영등포구에 유심 재발급 매장이 9곳 있다. SF12의 "매장 좀 찾고 있는데요"는 범위 밖 질문으로 분류됐다.
- **앱이 FAQ 조건을 한 번도 되묻지 않았다.** 조건에 따라 답이 갈리는 FAQ 8개 모두 바로 답했고, 답을 찾은 3개(CF01, CF02, CF08)는 경우별로 모두 답해 통과했다. 4개는 답을 찾지 못했고(CF03, CF05, CF07은 검색 실패, CF04는 비로그인 위약금 질문에 로그인 안내), CF06은 FAQ에 없는 절차를 덧붙여 근거 없는 답이 됐다.
- **비회원 요금제 추천 4개(CF09–CF12)는 나이·사용량을 되묻지 않았다.** "사용량을 알려주시면 추천해 드릴 수 있어요" 안내만 했다.
- **회원 데이터 답변은 계정 데이터와 일치한다.** 내 요금제, 사용량, 예상 요금, 약정, 위약금 답변이 모두 근거와 맞았다. 실패는 아래와 같다.
  - MD04: 남은 약정 개월 수를 직접 말하지 않았다(24개월 중 8개월 경과, 종료일만 안내).
  - MD06: 내 사용량 기반 추천 질문이 요금제 경로로 가지 않고 일반 안내로 답했다.
  - MD08 둘째 턴: "그럼 위약금은요?"가 문맥을 잃었다.
  - MD10: 회원 데이터가 없는 멤버십 등급 질문에 등급 혜택을 늘어놓았다(DeepSeek만 실패로 판정, 결합에서 실패).

## 모델끼리 갈린 턴

- MD09 둘째 턴: "지금 쓰는 5G 스탠다드가 사용량에 알맞아요"는 평균 28.5GB와 제공량 50GB를 앱 규칙으로 비교한 결론이다. Qwen은 근거 있음, DeepSeek와 Mistral은 근거 없음으로 봤다.
- MD10: 위와 같다. Qwen과 Mistral은 통과로 봤다.

## 한계

- 판정은 한 번 실행한 값이고 사람 판정은 없다.
- 고객 답변은 시나리오 작성자가 쓴 고정 문장이다. 앱이 평가셋에 없는 조건을 되물으면 사람 검토로 둔다(이번 실행에는 없었다). 매장 시나리오 중 업무 답변이 없던 것은 기대 업무로 만든 답변(`auto`)을 썼다.
- 좌표 답변은 그 지역 매장 좌표의 평균이다. 지명 매장은 4개뿐이다.

## 파일

원시 파일은 `raw.tar.xz` 하나로 묶었다.

- `capture.json`: 매장·되묻기는 첫 캡처, 회원은 재캡처(`memberCasesFrom`), 지명 매장은 카카오 키 설정 뒤 캡처(`kakaoCasesFrom`)를 합친 캡처
- `qwen.json`, `deepseek-v3.2-usw2.json`, `mistral-large-3.json`: 모델별 판정(지금 코드 규칙으로 다시 집계)
- `combined-*.json`: 결합 판정과 턴별 모델 판정
- `manifest.json`, `manifest-member.json`, `manifest-kakao.json`: 세 캡처의 실행 기록

```powershell
mkdir .measure/flows-v1-result
tar -xf docs/03-evaluation/chat-judge/results/20261016-flows-v1/raw.tar.xz -C .measure/flows-v1-result
python -X utf8 -m scripts.chat_judge.combine_judges .measure/flows-v1-result/qwen.json .measure/flows-v1-result/deepseek-v3.2-usw2.json --capture .measure/flows-v1-result/capture.json
```
