BE 전용 브랜치: `test/TELME-107-chat-session-recovery`. 원래 검증 기준은 `fix/TELME-105-plan-question-explanation` `cd7df7cc75f75254844f83f7abf39970b10172fb`다. 시작 당시 원본 105에는 미커밋 변경이 없었다. 별도 작업본·브랜치를 만들었고 기존 변경을 보존했다. 별도 브랜치/커밋 규칙 파일은 찾지 못했고 백엔드 저장소의 PR 양식과 이슈 키 관례를 따랐다.

## 기존 백엔드 계약과 검증

기존 BE 저장·소유권·이력 커서·runningExecutionId·근거 API를 재사용했다. 상담 조건은 서버 DB 상태를 기준으로 판단한다.

- 세션 ID만으로 접근할 수 없으며 기존 서버 인증·소유권 검증을 거쳐야 한다. 타인 식별자로 이력을 조회하면 거절되고 상담 조건은 바뀌지 않는다.
- 독립된 GET 이력 요청을 반복해도 상담 조건·원래 asked_message_id·대기 상태가 유지된다. 생성 중 미완료 본문과 완료 답변은 구분된다.
- 기존 이력 응답의 runningExecutionId와 종료 상태를 재사용한다. GET 이력 조회가 새 실행을 만들지 않는지 확인한다.
- 완료 답변과 근거는 기존 이력 API 및 `/api/v1/chat/messages/{messageId}/sources`로 확인한다. 오류·취소·타임아웃 상태는 정상 완료와 구분한다.
- 기존 105의 설명은 ANSWER이고 원래 PENDING 질문은 유지된다. 설명 후 입력은 설명 메시지가 아닌 기존 대기 질문의 조건에 반영된다.

백엔드 기능·API/SSE 형식·Guard·Router·모델·검색·프롬프트·평가·스키마는 변경하지 않았다. 이번 보완은 기존 계약을 확인하는 통합 테스트 1건과 검증 자료, CI 대상 설정이다.

## 시나리오별 기대와 실제 결과

아래 표는 저장된 합성 사례의 서버 기록만 정리한다. 자동 통합 테스트는 독립 HTTP 조회와 후속 입력을 검증한다. JSON은 서버 기록을 발췌한 자료이며 전체 원본은 로컬에 별도로 보존한다. 이 자료를 팀 화면의 재현 완료 결과로 사용하지 않는다.

E는 타이밍 확인을 위해 동일 질문을 수동으로 두 번 제출한 서버 기록이다. 세션 763에 입력·실행·답변이 각각 두 건이며 세 번째 실행은 없다. 이것만으로 실제 화면의 자동 재전송 방지나 네트워크 재접속 동작이 검증됐다고 해석하지 않는다.

FAQ 357(BILLING-0001)은 월 1회·가입월 변경 불가·다음 달부터 가능, 1387(BILLING-0015)은 월 1회·가입월 변경 불가, 1462(BILLING-0106)은 월 1회·이번 달 이미 변경한 경우 다음 달·가입월 제한을 명시한다. 각 실행의 실제 검색 결과·순서·점수는 공유 JSON에 별도로 보존했다. 서로 다른 실행의 FAQ를 동일 근거로 섞지 않는다.

## 자동 검증과 재사용

BE 전용 JDK21/PostgreSQL/PostGIS/pgvector 전체 build: **1,498건 중 통과 1,496건, 실패·오류 0건, 평가 프로브 스킵 2건**. 활성 Chat 통합은 기존 68건에 복원 요청·조건 불변·설명 연결·최종 이력·타인 접근 거절 사례 1건을 더한 69건이다. 이 검증은 모델/검색 대체이며 실제 모델 브라우저 사례와 구분한다.

TELME-92/93의 Guard 검증 후 전송, 정상/수정/안전 안내 저장·조회 동일성, 생성 중 내용 null, 실패·타임아웃·취소, 중복 완료, 저장 후 전송 실패, 종료 실행 SSE 재구독 회귀를 재사용했다. 98·104·105의 후속 입력·정정·조건 동시 입력·설명 후 상담 재개도 같은 전체 실행에 포함한다. 기존 선택/전체 수치를 합산하지 않는다.


## 남은 범위

- 팀 실제 화면의 새로고침·재접속·표시와 브라우저 SSE 연결은 미검증이다. 백엔드 통합·SSE 자동 회귀 통과와 화면 검증 완료를 동일시하지 않는다. 화면 검증은 담당자와 별도로 진행한다.
- 물리적 오프라인 복구, 화면 조회 타임아웃, 실제 실패 실행의 재접속 화면은 미검증이다. 기존 백엔드 실패·취소·타임아웃 회귀는 재사용했다.
- 로그인 전환/쿠키 상실/서버 재시작 후 게스트 접근은 별도 환경 검증이 필요하다. 세션 포인터 보존만으로 인증 복구를 주장하지 않는다. 상담 조건은 서버 DB에 남아도 게스트 HttpSession이 사라지면 기존 권한 없이 접근할 수 없다.
- 모델 품질·전체 환각률 개선은 측정하지 않았다. 화면 복원 성공을 해당 지표로 표현하지 않는다.
