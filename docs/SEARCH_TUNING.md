# FAQ 검색 품질 튜닝 보고서

---

## 1. 배경

### 1.1 대상 시스템

- 사용자 질문을 받아 FAQ 1,150건 중 관련 항목을 찾아주는 벡터 검색
- 동작 순서
  1. 질문을 임베딩 모델(`bge-m3`)로 1,024차원 벡터로 변환
  2. pgvector가 FAQ 벡터 중 코사인 거리가 가까운 상위 k건 반환
  3. 유사도가 임계값 미만이면 결과에서 제외 (= "관련 FAQ 없음" 응답)

> 코사인 유사도: 두 벡터가 이루는 각도의 코사인값. 1에 가까울수록 의미가 유사. pgvector의 `<=>`는 코사인 거리(1 - 유사도)를 반환.

### 1.2 이번 튜닝에서 정한 값

| 설정 | 위치 | 역할 |
| --- | --- | --- |
| 임베딩 텍스트 구성 | `faq.embedding-text.variant` | FAQ의 어느 부분을 벡터로 만들지 |
| 유사도 임계값 | `search.similarity-threshold` | 이 값 미만은 결과에서 제외 |
| top-k | `FaqSearchRequest.DEFAULT_TOP_K` | 후보를 몇 건까지 반환할지 |

### 1.3 세 값의 상호 의존

- 구성마다 점수 분포가 달라 최적 임계값이 0.72~0.85로 상이 (7절)
- 임계값에 따라 유효 top-k가 달라짐 (8절)
- 결론: 하나를 변경하면 나머지를 재측정해야 함
- 선행 작업 문제점
  - TELME-55: 구성과 무관하게 임계값만 결정
  - TELME-58 초기: 임계값과 무관하게 구성만 결정

## 2. 지표 정의

| 지표 | 정의 | 해석 |
| --- | --- | --- |
| Recall@k | 검색 결과 상위 k건 안에 정답 FAQ가 있는 질문의 비율 | 높을수록 좋음 |
| MRR | 정답 순위의 역수 평균 (1등 1.0, 2등 0.5, 3등 0.33, 못 찾으면 0) | 순위까지 반영 |
| 무관 질문 거부율 | FAQ로 답할 수 없는 질문에 "결과 없음"을 반환한 비율 | 높을수록 오답 위험 낮음 |
| AUC | 무작위로 뽑은 (정답 점수, 무관 질문 점수) 쌍에서 정답 점수가 더 높을 확률 | 임계값과 무관한 분리도 지표. 1.0 완전 분리, 0.5 무작위 |

> Recall@k와 거부율은 임계값에 따라 반대 방향으로 움직임. 임계값을 올리면 거부율은 오르고 Recall은 떨어짐.

## 3. 확정값

| 설정 | 확정값 | 변경 전 | 근거 절 |
| --- | --- | --- | --- |
| `faq.embedding-text.variant` | `Q_A` (질문 + 답변) | 동일 (유지) | 7절 |
| `search.similarity-threshold` | **0.72** | 0.7 | 6절 |
| `FaqSearchRequest.DEFAULT_TOP_K` | 3 | 동일 (유지) | 8절 |
| `search.dual-vector.enabled` | **true** | false | **15절** |
| `search.dual-vector.question-threshold` | **0.88** | 신규 | **15절** |

확정값 적용 시 성능

| 지표 | 단일 벡터 (1차) | **이중 벡터 (현행)** |
| --- | --- | --- |
| Recall@1 | 0.312 | **0.412** |
| Recall@3 | 0.375 | **0.463** |
| MRR | 0.338 | **0.435** |
| 무관 질문 거부율 (50건) | 0.940 | **0.940** |
| 무관 질문 거부율 (70건) | 0.886 | **0.886** |

## 4. 측정 환경과 방법

### 4.1 환경

| 항목 | 값                                                      |
| --- |--------------------------------------------------------|
| 코퍼스 | `scripts/data/faq_full_1150.json` 1,150건 + dev 시드 2건   |
| 평가셋 | `scripts/data/eval_questions_130.json` (긍정 80 + 무관 50) |
| 임베딩 모델 | `bge-m3`, 1,024차원                                      |
| 측정 스크립트 | `scripts/measure_search_quality.py`                    |
| 격자 분석 | `scripts/analyze_search_grid.py`                       |

### 4.2 격자 설계

- 비교 대상: 구성 4 × top-k 4 × 임계값 31 = 496조합
- 단순 반복 시 소요: 조합당 약 2분 40초 × 496 ≈ 22시간
- 실제 소요: 약 11분

비용 절감 원리

- 검색 결과는 점수 내림차순으로 정렬됨
- 따라서 임계값과 top-k는 이미 받은 결과를 다시 거르면 계산 가능
  - top-k 축소: 하위 순위 제거
  - 임계값 상향: 기준 미만 제거. 정답이 임계값을 통과하면 그 앞 순위도 모두 통과
- 실제 측정은 구성별 1회만 수행 (임계값 0, top-k 10으로 넉넉히 수집)
- `--dump-json`으로 질문별 원시 결과(순위, 점수, FAQ 식별자)를 저장 후 오프라인 계산

### 4.3 측정 원칙

- 순위 실험은 임계값 0으로 수집: 임계값을 켜면 "랭킹 품질"과 "임계값 컷"이 한 숫자에 혼재
- 같은 DB 상태에서 재측정 시 값이 완전히 동일함을 확인

## 5. 평가셋

### 5.1 구조

```
SIMILAR        40건  FAQ 질문과 유사한 표현
VARIANT        40건  같은 FAQ를 크게 다른 표현으로
UNRELATED      50건  FAQ로 답할 수 없는 질문
  ├ OFF_DOMAIN     16건  통신과 무관 (날씨, 요리, 영화)
  ├ ADJACENT       24건  통신이지만 FAQ에 없음 (인터넷 결합, 단말 보험)
  └ ADJACENT_HARD  10건  FAQ에 소재는 있으나 FAQ가 답하지 않는 측면
```

- 대상 FAQ 40건: 카테고리 10종 × 4건, 각 FAQ에 SIMILAR/VARIANT 1문항씩
- 정답 필드는 배열 허용 (답변이 사실상 같은 FAQ가 여럿일 때 모두 정답 처리, 현재 4문항)
- 정답 필드는 TELME-73부터 `expected_slot_id`. 이 문서의 수치는 `expected_content_hash` 기준으로 측정했다. 전환 후 `Q_A` 1,150건 코퍼스에서 130건을 다시 측정한 결과(Recall, 거부율, 격자 분석)는 전환 전과 같았다

### 5.2 30건 → 130건 확대 사유

| 항목 | 기존 30건 | 신규 130건 |
| --- | --- | --- |
| 긍정 질문 | 20 | 80 |
| 무관 질문 | 10 | 50 |
| Recall 95% 신뢰구간 | ±0.218 | ±0.109 |
| 카테고리당 긍정 질문 | 2 | 8 |

- 문제: 긍정 20문항 기준 오차 ±0.218. 임베딩 구성 4안의 차이(0.05)를 구분 불가
- 비교 대상보다 측정 오차가 4배 큰 상태였음

> 신뢰구간 계산: 비율 p의 표준오차 = √(p(1-p)/n). p=0.5, n=20이면 ±0.218, n=80이면 ±0.109. 오차를 절반으로 줄이려면 문항 수는 4배 필요.

### 5.3 대상 FAQ 선정 기준

- 다른 FAQ와의 답변 유사도 최댓값이 0.90 미만인 FAQ만 선정 (쌍둥이 FAQ 회피, 11절)
- 정책 항목(`policy_ref`)이 서로 겹치지 않도록 분산
- 답변 길이 25자 이상

검증 결과

| 채점 방식 | Recall@1 |
| --- | --- |
| 엄격 (지정 정답만 인정) | 0.537 |
| 관대 (답변 유사도 0.95 이상 FAQ도 정답 인정) | 0.537 |

- 차이 0 = 쌍둥이로 인한 채점 왜곡 없음
- 기존 30건 평가셋에서는 같은 비교에서 0.05 차이 발생 (과소평가 상태였음)

### 5.4 경계 질문(ADJACENT_HARD) 추가 사유

- 문제: 무관 질문 40건의 점수 최댓값이 0.6866 → 임계값 0.69 이상 구간에서 거부율이 모두 1.000
- 결과: 0.69와 0.80의 성능 차이를 측정 불가

| 임계값 | 거부율 (경계 질문 제외 시) | 거부율 (경계 질문 포함 시) |
| --- | --- | --- |
| 0.66 | 0.975 | 0.780 |
| 0.69 | 1.000 | 0.800 |
| 0.72 | 1.000 | 0.940 |

- 경계 질문 10건 추가 후 무관 질문 점수 최댓값 0.6866 → **0.7913**
- 경계 질문 예시

```
FAQ 내용:  "유심 재발급 비용이 얼마예요?" → "7,700원입니다"
경계 질문: "유심 재발급 비용은 현금영수증 발급이 되나요?"   (결제, 증빙 관련 답변 없음)
경계 질문: "eSIM 발급 비용 2,750원은 부가세가 포함된 금액인가요?"  (부가세 언급 없음)
```

- 제작 시 주의: 점수가 높은 질문은 대부분 실제로 답이 존재. 후보마다 검색 1위 답변을 확인해 "답이 없음"을 사람이 판정해야 함
- 오판 사례: "번호이동은 몇 시까지 신청해야 당일 처리되나요?" (점수 0.8261) → FAQ가 실제로 답함(09:00~20:00). 무관 질문에서 제외

## 6. 임계값 결정 근거

### 6.1 임계값별 성능

| 임계값 | Recall@3 | 거부율 | 직전 대비 변화 |
| --- | --- | --- | --- |
| 0.70 | 0.438 | 0.820 | - |
| 0.71 | 0.400 | 0.880 | 거부 +0.060 / 정답 -0.038 |
| **0.72** | **0.375** | **0.940** | 거부 **+0.060** / 정답 **-0.025** |
| 0.73 | 0.350 | 0.940 | 거부 +0.000 / 정답 -0.025 |
| 0.74 | 0.287 | 0.940 | 거부 +0.000 / 정답 -0.063 |
| 0.75 | 0.275 | 0.940 | 거부 +0.000 / 정답 -0.012 |
| 0.76 | 0.225 | 0.960 | 거부 +0.020 / 정답 -0.050 |

- 0.73~0.75: 거부율 상승 없이 정답률만 하락하는 순손실 구간
- 0.76: 거부율 2%p 확보에 정답률 5%p 소모

### 6.2 문항 수 기준 손익 (긍정 80 / 무관 50)

| 변경 | 정답 손실 | 무관 차단 증가 | 차단된 질문 종류 |
| --- | --- | --- | --- |
| 0.71 → 0.72 | 2문항 | 3건 | 전부 경계 질문 |
| 0.71 → 0.76 | 14문항 | 4건 | 전부 경계 질문 |

- 0.72 선택 근거
  - 교환비가 유지되는 마지막 지점
  - 차단 대상이 경계 질문(오답 위험이 큰 유형)
  - 정답 손실은 "관련 FAQ 없음" 응답으로 처리되어 재질문 가능

### 6.3 확정값에서의 종류별 거부율

| 무관 질문 종류 | 거부율 |
| --- | --- |
| OFF_DOMAIN (완전 무관) | 1.000 |
| ADJACENT (도메인 인접) | 1.000 |
| ADJACENT_HARD (경계) | 0.700 |
| 전체 | 0.940 |

### 6.4 선택 규칙과 조정 경위

- 초기 규칙: 무관 거부율 ≥ 0.95 제약 하 Recall@3 최대
- 규칙 적용 결과: 0.76 (Recall@3 0.225)
- 조정: 하한을 0.94로 완화해 0.72 선택. Recall@3 0.225는 서비스 적용 곤란

민감도 (제약 하한 변경 시 최적점 이동)

| 거부율 하한 | 선택 구성 | 임계값 | Recall@3 |
| --- | --- | --- | --- |
| 0.90 | QUESTION_ONLY | 0.80 | 0.537 |
| 0.95 | QUESTION_ONLY | 0.85 | 0.450 |
| 1.00 | CATEGORY_Q_A | 0.79 | 0.125 |

- 거부율 1.00 요구 시 Recall@3이 0.125까지 하락. "무관 질문 100% 차단"의 비용이 큼

### 6.5 값 해석 시 전제 조건

| 전제 | 내용 |
| --- | --- |
| 무관 질문 난이도 | 임계값은 "무관 질문 점수 최댓값"보다 위여야 함. 더 어려운 질문 추가 시 상승 |
| 평가셋 구성비 | 긍정 80 : 무관 50 = 무관 38%. 실제 트래픽 비율이 아님 |
| 임베딩 구성 | 구성 변경 시 무효 (7절) |

측정별 결론 차이 (동일 코퍼스, 평가셋만 상이)

| 측정 | 무관 질문 | 무관 점수 최댓값 | 결론 |
| --- | --- | --- | --- |
| TELME-55 | 10건 | 0.7236 | 0.71 |
| TELME-58 1차 | 40건 | 0.6866 | 0.69 |
| TELME-58 2차 | 50건 | 0.7913 | **0.72** |

- 세 측정 모두 각자의 데이터 범위 안에서는 정합적
- 경계 질문이 포함된 2차 값이 가장 보수적

## 7. 임베딩 텍스트 구성 결정 근거

### 7.1 후보와 측정 결과

| 구성 | 조립 형태 | AUC | 최적 임계값 | Recall@3 | 거부율 |
| --- | --- | --- | --- | --- | --- |
| QUESTION_ONLY | 질문 | **0.8756** | 0.85 | 0.450 | 0.960 |
| CATEGORY_Q_A | `[카테고리] 질문 답변` | 0.8508 | 0.74 | 0.287 | 0.960 |
| **Q_A (확정)** | `질문 답변` | 0.8390 | 0.72 | 0.375 | 0.940 |
| Q_A_HEAD200 | `질문 답변앞200자` | 0.8390 | 0.76 | 0.225 | 0.960 |

### 7.2 QUESTION_ONLY를 채택하지 않은 사유

**(1) 통계적 유의성 부족**

- 부트스트랩 1,000회로 AUC 차이 구간 추정

```
QUESTION_ONLY - Q_A : 중앙 +0.0358, 95% 구간 [-0.0215, +0.0988]
0보다 클 확률 0.902
```

- 구간이 0을 포함 → 우위를 확정할 수 없음

> 부트스트랩: 보유 표본에서 중복을 허용해 같은 크기로 재추출하는 절차를 반복해 통계량의 변동 범위를 추정하는 방법.

**(2) 평가셋 편향**

- 긍정 질문 80건이 모두 FAQ **질문**을 변형한 것
- 질문끼리 비교하는 구성에 구조적으로 유리
- 답변에만 있는 값("7,700원", "3 영업일")으로 묻는 질문이 평가셋에 거의 없음

**(3) 기능 손실 미측정**

- 질문만 임베딩 시 답변 본문이 벡터에서 제외
- "위약금 50%가 뭐예요" 유형 질문 검색 불가
- 해당 손실이 현재 평가셋에 반영되지 않음

후속 조건: 답변 내용을 묻는 질문 20건 추가 후 재측정. 손실까지 포함해 비교한 뒤 결정

### 7.3 기타 관찰

- `CATEGORY_Q_A`: 카테고리 접두사는 같은 카테고리 FAQ가 모두 공유하므로 문서 간 구분에 기여하지 않음. Recall@3 최하위
- `Q_A_HEAD200`: 답변이 200자를 넘는 FAQ가 0건이라 `Q_A`와 입력 문자열이 동일 (재임베딩 로그 `답변 잘림 0건`). 이슈 8(청킹 도입 여부)에서 "분할 대상이 없음"의 근거로 사용 가능

## 8. top-k 결정 근거

임계값 0.72 적용 시 top-k별 성능

| top-k | Recall@1 | Recall@3 | Recall@5 | MRR |
| --- | --- | --- | --- | --- |
| 1 | 0.312 | - | - | 0.312 |
| **3** | 0.312 | 0.375 | - | 0.338 |
| 5 | 0.312 | 0.375 | 0.375 | 0.338 |
| 10 | 0.312 | 0.375 | 0.375 | 0.338 |

- top-3 이상에서 값이 동일. 임계값이 3순위 이전에 후보를 제거하기 때문
- top-k 확대가 의미를 가지려면 임계값 하향이 선행되어야 함
- 기존값 3 유지

> **후속(TELME-59)**: 응답 지연시간과, 임계값을 낮춘 상태에서의 top-k 효과를 `docs/TOPK_LATENCY.md`에서 재검증함: 임계값을 낮춰도 top-k 확대 효과는 커지지 않고, top-10은 top-5 대비 이득이 없다는 결과가 나와 위 "기존값 3 유지" 결정이 재확인됨.

## 15. 이중 벡터 (TELME-83)

1차 결론: 문제는 랭킹이 아니라 컷이다. 정답이 상위 3개에 와 있는데 임계값에서 잘리는 질문이 25건. 6.4절대로 임계값만 내리면 거부율이 같이 무너진다.

이중 벡터는 임계값을 안 건드리고 **신호를 하나 더 얹는다.** 같은 FAQ를 `QUESTION_ONLY`로 한 번 더 임베딩해 두고, 두 벡터를 각자의 임계값으로 조회해 합친다.

### 15.1 구성

| 항목 | 값 |
| --- | --- |
| 저장 | `embedding`(`Q_A`) + `embedding_question`(`QUESTION_ONLY`), 둘 다 `vector(1024)` |
| 인덱스 | 컬럼마다 HNSW `vector_cosine_ops` |
| 임계값 | `Q_A` 0.72 / `QUESTION_ONLY` 0.88 |
| 합치기 | 중복 제거, `QUESTION_ONLY` 우선, top-3 컷, 순위 재부여 |
| 비용 | 임베딩 호출 1회 그대로, DB 조회만 2회 |

두 점수는 **섞어 정렬하지 않는다.** `QUESTION_ONLY`는 짧은 문장끼리 비교해 점수가 전반적으로 높다. 한 줄로 세우면 척도가 다른 값을 비교하게 된다.

### 15.2 임계값 재탐색

선택 규칙을 측정 전에 고정했다: **무관 70건 거부 >= 62건, `ANSWER` 손실 0건. 그중 Recall 최대.**

| t | 기존 긍정 80 | `ANSWER` 30 | 무관 70 거부 |
| ---: | ---: | ---: | ---: |
| 0.85 | 40 | 22 | 60 |
| 0.87 | 37 | 22 | 61 |
| **0.88** | **37** | **22** | **62** |
| 0.89 ~ 0.92 | 36 | 22 | 62 |
| 0.95 | 33 | 22 | 62 |

0.85가 Recall은 높지만 거부율을 깎는다. 0.87로 내리면 `EVAL-175`(질문만 점수 0.877)가 통과한다. **0.88은 여유가 0.003이다.**

### 15.3 실측

플래그를 켠 실제 구성으로 쟀다. 시뮬레이션(`EVAL_SET_SUPPLEMENT.md` 6절)과 일치했다.

| 지표 | 단일 벡터 | 이중 벡터 |
| --- | ---: | ---: |
| Recall@3 (양성 80) | 0.375 (30) | **0.463 (37)** |
| Recall@1 | 0.312 | 0.412 |
| MRR | 0.338 | 0.435 |
| 무관 70건 거부 | 62 | 62 |
| `ANSWER` 30건 | 22 | 22 |
| `ANSWER` 세부(커버됨/답변에만) | 14 / 8 | 14 / 8 |
| 경계 무관 30건 거부 | 22 | 22 |
| 지연 (1회 측정) 평균 / p95 | 67.3ms / 111.5ms | 61.6ms / 85.2ms |
| 지연 (3라운드) 중앙값 / p90 | 45.2ms / 53.2ms | 49.8ms / 58.5ms |

- 기존 성공 30건 중 깨진 문항은 **실측상 0건**이다. 구조적으로 보장되는 성질은 아니다. `DualVectorMerger`가 질문 벡터 결과를 먼저 넣고 top-3에서 자르므로, 질문 벡터가 비정답 FAQ 3개를 먼저 채우면 기존 `Q_A` 정답이 4위로 밀려 빠진다. 이번 평가셋에서는 밀려난 비정답이 최대 1개라 여유가 2개 있었다(30건 중 25건은 0개, 5건은 1개)
- 살아난 7건: `EVAL-006, 007, 013, 014, 025, 037, 040`. 전부 `QUESTION_ONLY`가 0.884 ~ 0.991로 잡았다
- **지연은 측정 편차 수준이다.** 1회 측정에서는 이중 벡터가 빨라 보이지만, 130문항 x 3라운드(워밍업 2회 후) 재측정에서는 약 5ms 느린 방향이다(TELME-84). 두 측정은 지표가 달라(평균/p95 vs 중앙값/p90) 절대값을 비교하지 않는다. 체감 차이 없음
- `SEARCH_FAILURE_ANALYSIS.md` 7절에서 확인된 HNSW 후보 집합 변동은 이번에도 지표에 영향이 없었다. 재임베딩 후 재수집에서 top-10 후보가 바뀐 문항이 4건 있었으나, 같은 후보끼리의 점수와 지표는 같았다(TELME-84)

살아난 질문은 성격이 같다. **뜻은 같은데 말투가 달라 `Q_A` 벡터가 답변 단어에 끌려 못 잡던 것들.**

```
"휴대폰을 분실했을 때 가장 먼저 무엇을 해야 하나요?"
   -> "폰 잃어버렸을 때 뭐부터 해야 해요?"   0.930
```

| EVAL-058 | 가입한 지 얼마 안 됐는데 바꾸고 싶습니다 | 위와 같은 FAQ | 사실상 정답 |
| EVAL-005 | 한 번 교환한 단말 다시 교환되나요? | 기기변경 직후 교환 **절차** | 오답 |
| EVAL-055 | 제일 싼 알뜰 상품 월 얼마, 데이터 얼마 | 제일 싼 요금제 **가입 가능 여부** | 오답 |

앞 3건은 질문에 답이 되는 근거를 전달받는다. 채점만 오답으로 센다. 정답 라벨이 FAQ 1건만 지정해서다(11절 쌍둥이 FAQ와 같은 뿌리).

> **실질 위험 실패는 2건(EVAL-005, 055).** 둘 다 "주제는 같은데 묻는 항목이 다른" 유형이라 `ADJACENT_HARD`와 성격이 같다. 검색에서 더 거르기보다 근거 적합성 판정이 맡는 쪽이 맞다.

정답 위치로 나누면 필요한 수단이 갈린다.

| 정답이 어디 있나 | 건수 | 수단 |
| --- | ---: | --- |
| top-3인데 임계값에 걸림 | 25 | 어휘 게이트. 25건이 구제 상한이라 Recall@3 0.463 -> 최대 0.775. 실제 이득은 미측정 |
| 4 ~ 10위 | 6 | 리랭커 |
| 양쪽 벡터 모두 top-10 밖 | 12 | 질문 재작성 / FAQ 변형 색인 |

**12건이 가장 어렵다.** FAQ와 공유 단어가 없어 어떤 벡터로도 안 잡힌다(3.2절 B4). 계획만 있고 착수 안 했다.

### 15.5 AI 파트 재측정이 남았다

이 절 수치는 전부 **검색이 근거를 전달했는가**까지다. 그 근거로 LLM이 잘 답하는지는 `ANSWER_QUALITY.md` 몫이고, 이중 벡터 도입 후로는 안 쟀다. 달라진 입력은 셋이다.

- 새로 근거를 받는 7건: LLM이 제대로 답하는지
- 위험 실패 2건: 근거 적합성 판정(`rag.evidence-check`, 현재 꺼짐)이 잡는지
- 근거 출처가 섞인다: `matchedVariant`가 `QUESTION_ONLY`인 결과는 점수 분포가 다르다(0.88 ~ 0.99). 점수로 판단하는 로직이 있으면 확인 필요

### 15.6 재현

```bash
# 0) 백필: 로더 1회(slot_id) + 재임베딩 1회(질문 벡터, 약 140초)
FAQ_BATCH_LOAD_ENABLED=true FAQ_BATCH_LOAD_PATH=scripts/data/faq_full_1150.json \
  FAQ_BATCH_LOAD_EXIT_AFTER=true java -jar build/libs/telme-0.0.1-SNAPSHOT.jar
FAQ_REEMBED_ENABLED=true FAQ_REEMBED_EXIT_AFTER=true \
  java -jar build/libs/telme-0.0.1-SNAPSHOT.jar

# 1) 정합성: qo_null과 same이 0, 지문은 4.1절 기준값과 같아야 한다
docker exec telme-postgres psql -U telme -d telme -c \
  "select count(*) total, count(*) filter (where embedding_question is null) qo_null,
          count(*) filter (where embedding = embedding_question) same from faq_embeddings;"

# 2) 벡터별 top-10 수집. 두 임계값을 0으로 푼 서버에서 --vector로 고른다(TELME-84)
#    서버: FAQ_SEARCH_TEST_API_ENABLED=true SEARCH_SIMILARITY_THRESHOLD=0 SEARCH_DUAL_VECTOR_QUESTION_THRESHOLD=0
#    130건과 보강 50건 모두 QA, QUESTION 각각 수집 (scripts/README.md 6절 "이중 벡터 임계값 재탐색")
python3 scripts/measure_search_quality.py scripts/data/eval_questions_130.json \
  --api-url http://localhost:18090/api/v1/faq/search --top-k 10 \
  --vector QA --dump-json .measure/raw-130-Q_A.json

# 3) 임계값 격자. --qo-thresholds는 쉼표 구분
python3 scripts/simulate_dual_vector.py \
  --qa .measure/raw-130-Q_A.json .measure/raw-supp50-Q_A.json \
  --qo .measure/raw-130-QUESTION_ONLY.json .measure/raw-supp50-QUESTION_ONLY.json \
  --qa-threshold 0.72 --qo-thresholds 0.85,0.87,0.88,0.89,0.90,0.92,0.95

# 4) 확정값 실측: 플래그 켠 기본 설정으로 top-3 측정
```

측정 환경은 4.1절과 같다. 측정일 2026-09-29, `develop` TELME-76 머지 시점.
