# 챗봇 출력 검사

## 목적과 처리 범위

- 챗봇의 최종 표시 문구에서 검증한 욕설·초성·변형을 검사한다.
- 사용자 입력 검사·개인정보 마스킹·경고 횟수·일시 제한과 별개다. 사용자 식별자나 제재 저장소를 사용하지 않는다.
- 기존 Answer Guard의 근거·금액·기간·조건 검증은 유지한다. 감지 판단이나 재생성에 별도 LLM을 호출하지 않는다.
- 모든 모욕적 의미·약어·무한한 우회 표기를 판별하는 기능은 아니다.

## 활성 처리 경계

`생성 → 기존 근거 Guard → 최종 조립 → 출력 검사 → 답변 저장 → SSE`

- `ChatExecutionService.completeAnswer`가 본문·추천 질문·매장 표시 값·검색 기준 라벨을 저장 전에 검사한다.
- 실제 저장할 JSON도 검사하고 같은 문자열을 저장해, 표시 목록이 검사 후 바뀌어도 미검사 문구가 저장되지 않도록 한다.
- `askClarification`은 되묻기 질문·선택지를 저장하기 전에 검사한다.
- 단일 FAQ·복합 FAQ·직접 응답·기본 대화·매장 결과가 공통 저장 경계를 사용한다.
- 복합 답변은 고객 질문이 제목에 포함되므로 모델 생성문만 검사하지 않고 조립 결과를 검사한다.
- 원시 생성 토큰은 기존 수집 경로를 유지한다. 활성 상담 SSE는 저장된 최종 답변만 전송한다.
- 기존 FAQ 근거 스냅샷·사용자 대화·요약·세션 제목을 소급 수정하거나 새 출력 검사 대상으로 확장하지 않는다.

## 규칙과 한계

- 규칙은 `src/main/resources/chat/output-guard-rules.json`, 버전은 `chat-output-guard-v1`이다.
- 인용이라고 해서 출력 욕설을 그대로 허용하지 않는다. 사용자 입력의 피해 인용 예외를 재사용하지 않는다.
- 일반 문자열은 NFKC로 정규화하고 호환 자모는 각각 정규화해 초성·울음 표기의 합성을 막는다.
- 표현 내부의 공백·점·별표·하이픈·숫자·지원 보이지 않는 구분자는 글자 사이 최대 6개까지 지원한다.
- 끝의 웃음·울음 자모는 최대 12개까지 지원한다.
- `시발점`, `시발역`, `시발열차`는 해당 구간만 예외이며 다른 구간의 욕설은 계속 검사한다.
- 정상 단어 일부를 연결하지 않도록 경계를 검사한다. 분리 표기의 어미는 더 좁게 지원한다.
- 앞말 결합은 설정의 `joinedPrefixes`, 붙임 문의는 코드의 `JOINED_QUERY`에서 검증한 범위만 지원한다.
- `바보`, 빈정거림, 동물·약어의 의미, 임의 한국어 문맥을 포괄하는 검사는 지원하지 않는다.
- 매장 표시 값은 검사만 하며 ID·좌표·이름 등 검색 결과를 임의로 수정하지 않는다. 중첩 자료는 깊이 8까지 검사한다.

| 문구 | 처리 |
| --- | --- |
| 다시 발급·시 발송·출시 발표·개통 시 발신 | 보존 |
| 병 신청·아저씨 발 사이즈·병 신임 교육 | 보존 |
| 씨발·병신아·씨.발·씨123발 | 차단 |
| 이거씨발·너병신·씨발요금 | 검증한 결합으로 차단 |
| 씨발ㅋㅋ·ㅂㅅㅠㅠ | 차단 |
| '병신'이라고 하셨네요 | 재인용 출력도 차단 |
| 시발역 안내 뒤에 다른 욕설이 있음 | 다른 욕설 구간 차단 |

## 차단·검사 오류 계약

| 사유 코드 | 의미 | 안내 |
| --- | --- | --- |
| `CHAT500-0` | 출력 정책 차단 | 답변을 안전하게 제공하지 못했습니다. 잠시 후 다시 시도해 주세요. |
| `CHAT500-1` | 출력 검사 실패 | 답변을 안전하게 확인하지 못했습니다. 잠시 후 다시 시도해 주세요. |

- 정상 입력 접수의 POST `201`·실행 ID 계약은 유지한다. 생성 후 출력 실패를 입력 차단의 `200`·실행 ID 없음과 혼동하지 않는다.
- 해당 실행은 `FAILED`, 출력 메시지는 `ERROR/FAILED`로 기록한다. 근거가 있는데 `NO_EVIDENCE`로 위장하거나 정상 완료로 저장하지 않는다.
- 차단 생성문 대신 고정 안내만 저장한다. 근거 답변 표시·추천 질문·매장 결과는 실패 메시지에 붙이지 않는다.
- 최초 SSE `error`와 종료 후 재구독은 같은 사유·고정 안내를 제공한다. 기록 조회의 `content`도 같은 안내다.
- 검사 오류도 후보를 그대로 통과시키지 않는다. 원문·예외 본문을 새 로그나 오류 응답에 넣지 않는다.
- 사용자 제재를 추가하지 않고 자동 재생성·자동 재전송·부분 답변 재구성을 하지 않는다.
- 상담을 임의 완료하지 않는다. 되묻기 검사 실패는 질문·조건·계획 저장 트랜잭션을 완료하지 않는다.
- 기존 취소·타임아웃·소유권·실행 종료 검사를 유지한다.

SSE `error` 데이터 예시:

```json
{
  "status": "FAILED",
  "errorCode": "CHAT500-0",
  "message": "답변을 안전하게 제공하지 못했습니다. 잠시 후 다시 시도해 주세요."
}
```

## 기록과 프런트 연결

- 실행 오류 코드는 기존 `chat_executions.error_code`를 활용한다. 별도 테이블·마이그레이션을 추가하지 않는다.
- 실행 추적의 `outputSafety`에는 차단 여부·정책 버전·고정 필드 구분·규칙 ID만 기록한다. 원시 생성문은 추가하지 않는다.
- 모델 호출 완료와 최종 출력 차단은 다른 결과다. 실제 호출 성공 기록을 허위로 삭제하거나 호출하지 않은 시도를 만들지 않는다.
- 추적 기록 실패가 고정 안내 저장·오류 이벤트 전달을 중단하지 않도록 격리한다.
- 프런트는 기존 실패 상태·`error` 이벤트를 사용하고 로딩을 종료한다. 사용자 욕설 경고나 제한 시간으로 표시하지 않는다.
- 이력에 `content`가 있는 실패 메시지는 해당 안내를 표시하고 별도 오류 문구를 중복 출력하지 않도록 연결한다.
- 실제 브라우저의 안내 표시·새로고침 복원은 소비 화면과 별도 검증해야 한다.

## 검증 방법

- 검사 단위에서는 정상 단어·인용 출력·초성·변형·앞말 결합·추천 질문·선택지·매장 표시·중첩 자료를 확인한다.
- 검색·모델 대역과 독립 개발 DB로 실제 활성 처리기·Guard·저장·이력 조회·SSE·재구독을 연결한다.
- 정상 근거의 저장과 전송, 차단 메시지 한 건, 원문 토큰 미노출, 차단 사유 분리, 상담 상태를 대조한다.
- 사용자 입력 검사와 결합한 검증에서는 기존 경고 이후 출력 차단이 제재 횟수·제한 종료를 변경하지 않는지 확인한다.
- 저장 실패·추적 실패·검사 실패·취소·타임아웃은 서로 구분한다.
- 자동 대역 테스트를 실제 모델 품질·전체 욕설 방지·화면 검증 완료로 표현하지 않는다.
