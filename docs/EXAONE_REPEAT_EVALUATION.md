- 기존 보고서: [문맥 판정](CONTEXT_RESOLUTION.md), [라우팅 호출별 비교](ROUTING_CALL_COMPARISON.md)

## 적용 범위와 한계

- 완전한 하드웨어 재현은 아닙니다. RTX 5070 Ti·CUDA·Windows의 Linux Docker 대신 Apple M4·Metal·macOS를 사용했습니다.
- Ollama 0.34.0 공식 네이티브 배포본 체크섬을 검증했고 EXAONE·bge-m3 manifest는 원본과 일치합니다.
- 현재 메모리는 전체 16 GiB 통합 메모리입니다. 전용 VRAM 16 GiB와 다르며, 기록에 없는 원본 RAM 제한을 임의로 설정하지 않았습니다.
- 문맥 판정은 c8bb0b2b에서 원본의 대상 판정 64토큰·출처 분석 max(64, min(2048, 128+64*n)) 한도를 적용했습니다.
- 문맥 평가는 원본 전체 채팅 API 실행 대신 resolver 전용 프로브를 사용했습니다. 스레드 수는 1, 흔들림 보완은 false입니다.
- #156 원본 미커밋 코드 patch가 없고, #160 실제 실행 커밋·검색 보정 DB도 확정되지 않았습니다.
- 과거 정답과 #160 코드 2c11759b를 고정했습니다. 프롬프트 조정이나 문항별 선택 재실행은 하지 않았습니다.
- 제공된 5440 FAQ·벡터 덤프를 독립 DB에 복원하고 전체 컬럼 값 일치를 검증했습니다.
- 실제 외부 API 키·모델 서비스는 사용하지 않았습니다. 검색 임베딩은 로컬 bge-m3입니다.
- 응답 시간은 관측값이며 동일 하드웨어 성능 비교로 해석하지 않습니다.

### 원시 기록의 인계와 재검증

저장소의 `.measure/` 및 문맥 실행 기록 제외 정책에 따라 원시 응답·DB 덤프·실행 로그는 커밋하지 않습니다.
원시 결과 ZIP은 TELME-183 첨부 대상으로 별도 보관합니다. 이 문서 작성 시 Jira 업로드는 수행하지 않았습니다.

- 파일명: `exaone-native-034-20261017.zip`
- SHA-256: `909d390f8cde235ca00ff3b9946e99dd5e02d2cc6f457e09025d07dc53c2a7a2`
- 로컬 보관 위치(저장소 루트 기준): `.measure/exaone-native-034-20261017.zip`
- ZIP 내부 경로는 아래 명령을 실행하는 압축 해제 디렉터리를 기준으로 합니다.

```bash
shasum -a 256 exaone-native-034-20261017.zip
unzip exaone-native-034-20261017.zip
cd exaone-native-034-20261017
shasum -a 256 -c checksums.sha256
```

실행별 명령과 환경 변수는 `results/*-execution.json`, 평가용 변경은 `results/adaptations/`,
채점 로직은 `score_results.py`에 보존했습니다. 실행 스크립트에는 당시 로컬 경로 의존성이 있으므로
새 장비에서 즉시 실행하는 범용 재현 도구로 간주하지 않습니다.
완전 재실행에는 과거 코드·모델·인계 DB 덤프·로컬 런타임을 다시 준비해야 합니다.
