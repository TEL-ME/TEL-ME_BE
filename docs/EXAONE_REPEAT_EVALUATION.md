- 기존 보고서: [문맥 판정](CONTEXT_RESOLUTION.md), [라우팅 호출별 비교](ROUTING_CALL_COMPARISON.md)

## 기존 gpt-oss 결과와 모델 선택

같은 평가셋의 기존 gpt-oss 결과를 함께 보면 이번 EXAONE 반복 평가로 기존 모델 선택을 바꿀 근거는 없습니다.

| 평가 | 문항 | EXAONE (이번 2회) | gpt-oss (기존 3회) |
| --- | ---: | --- | --- |
| 의도 분류 (검색 보정 후) | 365 | 334 / 334 | 362 / 361 / 360 |
| 요청 개수 v4 (단독 호출) | 210 | 200 / 200 | 203 / 204 / 202 |
| 문맥 기본 (1차, 흔들림 보완 끔) | 213 | 202 / 202 | 205 / 202 / 205 |
| 문맥 blind (1차, 흔들림 보완 끔) | 30 | 20 / 20 | 22 / 23 / 25 |

gpt-oss 값은 이번에 새로 호출한 결과가 아닙니다. 의도 분류·요청 개수는
[라우팅 호출별 비교](ROUTING_CALL_COMPARISON.md)의 1·2단계, 문맥은
[문맥 판정](CONTEXT_RESOLUTION.md)의 TELME-165 요약 중 1차·중계기 경로 값입니다.
평가셋은 같아도 모델·서빙 경로·실행 환경이 다른 기존 측정과의 비교이며, 동일 환경의 모델 교체 실험은 아닙니다.

의도 분류는 기존 gpt-oss 3회 모두 이번 EXAONE보다 높고, 문맥 기본은 같거나 높으며 blind는 모두 높습니다.
따라서 문맥·의도 분류를 gpt-oss로 전환하는 기존 결정을 유지합니다.
요청 개수는 단독 호출의 전체 점수만으로 켤지 정하지 않습니다. 기존 앱 흐름 평가에서는 의도 분류가
gpt-oss일 때 판정 호출을 끄는 편이 나았으므로, 그 조건에서 끄는 결정도 유지합니다.
이번에는 판정 호출을 끈 gpt-oss 경로를 재측정하지 않았습니다.

원본 EXAONE 1회(RTX·CUDA)와 이번 2회(M4·Metal)는 실행 조건이 달라 같은 조건의 3회 반복으로 합치지 않습니다.
이번 두 회는 문항별 판정까지 같았고 원본과는 의도 분류 3문항이 달랐습니다.
이를 이번 두 회 사이의 흔들림으로 해석하지 않고, 서로 다른 환경·실행 조건 사이의 차이로 구분합니다.
원본 실행 커밋·미커밋 상태가 확정되지 않아 하드웨어 등 특정 원인의 영향으로 단정하지는 않습니다.

## 적용 범위와 한계

- 완전한 하드웨어 재현은 아닙니다. RTX 5070 Ti·CUDA·Windows의 Linux Docker 대신 Apple M4·Metal·macOS를 사용했습니다.
- Ollama 0.34.0 공식 네이티브 배포본 체크섬을 검증했고 EXAONE·bge-m3 manifest는 원본과 일치합니다.
- 현재 메모리는 전체 16 GiB 통합 메모리입니다. 전용 VRAM 16 GiB와 다르며, 기록에 없는 원본 RAM 제한을 임의로 설정하지 않았습니다.
- 문맥 판정은 c8bb0b2b에서 원본의 대상 판정 64토큰·출처 분석 max(64, min(2048, 128+64*n)) 한도를 적용했습니다.
- 문맥 평가는 원본 전체 채팅 API 실행 대신 resolver 전용 프로브를 사용했습니다. 스레드 수는 1, 흔들림 보완은 false입니다.
- #156 원본 미커밋 코드 patch가 없고, #160 실제 실행 커밋·검색 보정 DB도 확정되지 않았습니다.
- 과거 정답과 #160 코드 2c11759b를 고정했습니다. 프롬프트 조정이나 문항별 선택 재실행은 하지 않았습니다.
- 제공된 5440 FAQ·벡터 덤프를 독립 DB에 복원하고 전체 컬럼 값 일치를 검증했습니다.
- 실제 외부 API 키·모델 서비스는 사용하지 않았습니다. 검색 임베딩은 로컬 bge-m3입니다.
- 응답 시간은 관측값이며 동일 하드웨어 성능 비교로 해석하지 않습니다.

- 요청 개수: 고정 평가셋·원본 응답, 요청 개수 단독 호출과 전체 FAQ 라우팅의 분해 결과

### 무결성과 재검증

각 README에 ZIP SHA-256과 압축 해제 후 `checksums.sha256` 확인 방법을 기록했습니다.
신규 모델 원시 응답은 원본 보관 파일과 바이트 단위로 동일하며, `results/scores.json`은 해당 단계만 추출했습니다.
공통 환경 정보와 당시 실행·채점 스크립트는 각 ZIP에 함께 보존하므로 전체 실험 설정도 포함합니다.
ZIP에 남아 있는 `/Users/`·`/private/tmp/` 절대 경로는 측정 당시 로컬 경로 기록이며,
다른 장비에서 바로 접근하거나 그대로 실행할 수 있는 경로가 아닙니다. 원시 기록의 경로는 변경하지 않았습니다.

`.measure/`와 `scripts/context-resolution-evaluation/runs/`는 계속 Git에서 제외합니다.
이번에 보존할 확정 결과만 위 `results/` 경로에 추가했으며, DB 덤프·모델 바이너리는 포함하지 않습니다.

실행별 명령과 환경 변수는 ZIP 내부 `results/*-execution.json`, 평가용 변경은 `results/adaptations/`,
채점 로직은 `score_results.py`에 보존했습니다. 실행 스크립트에는 당시 로컬 경로 의존성이 있으므로
새 장비에서 즉시 실행하는 범용 재현 도구로 간주하지 않습니다.
완전 재실행에는 과거 코드·모델·인계 DB 덤프·로컬 런타임을 다시 준비해야 합니다.
